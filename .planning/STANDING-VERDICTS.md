(`.planning/research/{STACK,FEATURES,ARCHITECTURE,PITFALLS,OPTIONS}.md`,

**Why this file exists:** `.planning/research/` is milestone-scoped and gets

## Design anti-features — attractive and wrong

- **Call-site override of a callee's declared ownership convention** — the C++
  overload-resolution cautionary case.
- **Whole-program / cross-module borrow inference** — the design Rust abandoned
  pre-1.0; breaks separate compilation and the evidence-manifest cache.
  Declared contracts instead; callee *signatures*, never callee bodies.
- **Implicit ARC-style refcount fallback** for arguments that don't cleanly
  move or borrow — hides runtime cost, directly against the core value.
- **Indirect / dynamic dispatch** (function pointers, closures, trait objects)
  in the call graph — closed typed dispatch is what makes cycle refusal and
  summary-based liveness tractable.
- **Implicit `From`-style error conversion** at a propagation operator —
  ambient conversion authority, against the no-ambient-authority constitution.
- **Silent depth-based stack growth** with no fixed documented ceiling.
- **A second, coexisting loan-liveness law** that doesn't retire the old one in
  the same phase (Key Lesson 2 — "two coexisting laws is a defect with a
  delayed fuse").
- **Formal SMT / Alive2-style proof of interprocedural equivalence** — Alive2,
  the state of the art, explicitly does not attempt interprocedural proof.
  Empirical differential testing is the right ambition here. Name it, don't
  schedule it.
- **A single `-O3` run with no engineered negative control** treated as
  equivalence evidence — a tier can look proven while being inert.

## Process anti-patterns

- **Don't bundle modules/separate compilation into a milestone already
  extending five-plus-consumer machinery.** M001's Phase 3 coordination cost
  (70-95 min/plan vs ~10 for single-consumer work) is the direct warning.
- **Don't Nyquist-validate a surface a milestone is about to change** — M001
  Phases 5/6 are deliberately carried as disclosed debt (QLT-09) for this
  reason.
- **Don't let spikes become scope-additive.** Stop when the gate is answered;
  a spike is throwaway workbench code, not production seed.
- **Don't build agent-loop/diagnostic support in parallel with semantic work.**
  The defect taxonomy isn't knowable until the semantics exist; building blind
  produces the wrong cause-DAG edges.
- **Don't skip a cost-scaling measurement before generalizing a local analysis
  across a boundary.** Go 1.18 generics and Rust's Polonius wall are precedent
  that this exact shape has a real cost cliff in the front end.
- **Don't defer the same debt item twice.** D-03-02 was carried past M001;
  carrying it past M002 would be a pattern, not a decision.

## Load-bearing technical facts worth not re-deriving

- **The six dispatch sites are literal, named, and test-enforced**, not a
  metaphor: `check`, `corevalidate`, `interp`, `cgen`, `pathoracle`,
  `originvalidate` — see `core.go:244-249` and `core_test.go`'s
  `TestAllOperationKindsHandledAtEverySite` (`control:kind.exhaustive_dispatch`).
  Registering a new `OperationKind` costs a **minimum of 8-10 independent
  edits** before it is real by the project's own D-04-22 standard.
- **`check.go:1316-1334` (`resolveForeignStep`) already refuses Lang callees**
  via `core.call_target_not_foreign`. M002 flips that existing refusal into a
  producer path — it is not a greenfield addition.
- **`cgen` is the outlier**: `Emit`/`EmitNative` hard-fail on
  `len(program.Functions) != 1` (`cgen.go:22,52`). Multi-function C emission is
  genuinely new infrastructure, not an incremental `case core.OpCall:`.
- **`interp` has no call-stack machinery at all** — no `Frame` type, no depth
  bound. Model the bounded stack on `pathoracle`'s existing fail-closed cap
  discipline (`MaxPaths` / back-edge refusal).
- **`core.Interface` / `core.FunctionSignature`** (body-stripped, digest-bound,
  built by `originvalidate.BuildInterface`) is the natural home for callee
  summaries — extend it rather than inventing a summary artifact.
- **`-flto` is load-bearing for the equivalence claim.** `restrict` and TBAA
  promises are per-translation-unit; without LTO, Clang cannot see across Lang
  call boundaries, so an interprocedural `-O3` claim would be inert by
  construction.
- **The content-bound cache needs call-graph-closure-derived keys** for any
  interprocedural fact. Per-unit hashes will silently serve stale verdicts when
  an unchanged caller's callee changes (precedent: Rust ThinLTO import-map
  invalidation, Bazel/Buck cross-module bugs).
