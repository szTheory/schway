**testsupport (D-07, D-12).** Create `checksum_oracle.go` with the types and functions listed in the Artifacts section.

`ChecksumReadFile` runs these steps in order:
1. `os.OpenFile(path, os.O_RDONLY|syscall.O_NONBLOCK, 0)`; an error returns `FileUnavailable`.
2. `f.Stat()`; an error or `!Mode().IsRegular()` closes and returns `FileUnavailable`.
3. `io.ReadAll(io.LimitReader(f, ChecksumLimit+1))`; a read error closes and returns `FileUnavailable`.
4. Check the `f.Close()` error explicitly. A close error returns `FileUnavailable`.
5. `len > ChecksumLimit` returns `FileTooLarge`.
6. Otherwise return the bytes, as a non-nil empty slice for an empty file, with an empty alternative.

Never call the whole-file read helper of package os, and never read the stat-reported size.

`ChecksumOracleRows()` builds its inputs with `bytes.Repeat` and returns 14 rows (7 inputs × apps `checksum` and `adler_low`) with the values in must_haves. `Cmd` is the exact generating command, for example `python3 -c 'import zlib;print(zlib.adler32(b"Wikipedia"))'` for checksum and `python3 -c 'import zlib;print(zlib.adler32(b"Wikipedia") % 65536)'` for adler_low. The 65,537 rows record both the size fact and the would-be checksum, so plan 31-08's `2273841137` assertion has a generating command:
- the `checksum` row's `Cmd` is `python3 -c 'import zlib;d=b"\xff"*65537;print(len(d)>65536, zlib.adler32(d))'`, which prints `True 2273841137`;
- the `adler_low` row's `Cmd` is `python3 -c 'import zlib;d=b"\xff"*65537;print(len(d)>65536, zlib.adler32(d) % 65536)'`, which prints `True 4081`.

Both rows have `Outcome: "FileTooLarge"` and `Want: 0`. The literal `2273841137` itself never appears in `checksum_oracle.go`. `Python` is `Python 3.14.4` on every row. Add a doc comment stating that the values come from Python zlib, are cross-checked by Go `hash/adler32` in plan 31-08, and are never derived from Schway.
