## Summary

I reviewed the Phase 32.1 diff (`558cbbae..HEAD`). The production changes are small: the `tool.run_input_required` refusal (exit 64), the ByteView entry refusal in the checker, the entry-module `main` rule in executionpeer, the widened abort-like defect predicate in the interpreter, `ModuleAwareRoutes`, and the script hardening. I found no data-loss or security defects. The run-input refusal message is a static constant, so it cannot leak the source path or parameter name. `ErrRunInputRequired` wraps `os.ErrInvalid`, so earlier callers keep working. Both engines go through the same `runInputRequiredResult`.

One real defect remains in the freeze gate. It does not behave the way its sibling script, `codedigest.sh`, was fixed to behave. The rest are quality items. I did not review the test files in depth beyond the new assertions.

## Warnings

### WR-01: `check-phase32-freeze.sh` gives a false pass when run outside the repo root

**File:** `scripts/check-phase32-freeze.sh:10-46`
**Issue:** This phase hardened `codedigest.sh` to `cd` to `git rev-parse --show-toplevel`, and `check-phase32-receipts.sh` already `cd`s to the root. The freeze gate does neither. It passes `$phase32_freeze_paths` ("cmd internal examples ...") to `git log` and `git diff` as cwd-relative pathspecs. Run from a subdirectory, those pathspecs match nothing, so `changed` is empty and `git diff --quiet` succeeds. I reproduced this:
- `cd cmd && sh ../scripts/check-phase32-freeze.sh 558cbbae... <HEAD>` prints `status=pass`.
- The same arguments from the repo root print `status=fail reason=digest_path_changed_after_freeze`.

The gate is fail-open, and it exists to bind receipts to frozen code. The new `:(exclude)*.md` pathspec was added to this exact line without fixing the cwd dependence.
**Fix:** Add this after `set -eu`, and reject if it fails:
```sh
root=$(git rev-parse --show-toplevel 2>/dev/null) || reject "no_repo_root"
cd "$root" || reject "no_repo_root"
```
Add a subdirectory test next to `subdirectory-equals-root` in `session_phase32_freeze_test.go`.

### WR-02: `isAbortLikeDefect` accepts any live resource set, and no longer checks the defect reason

**File:** `internal/compiler/interp/interp.go:432-461`
**Issue:** The predicate used to require `Output == "byte index out of bounds"` plus `OpBytesAt`. It now accepts any `function.defected` event whose operation kind is one of four. The comment justifies this only for the "fixture/file owner" being reclaimed by the OS. The callers (`RunWithFixtureBytes` and `RunWithFileBytes`) skip the live-resource rejection for every entry in `result.LiveResources`, not just the owner. A defect while an unrelated live local resource exists is therefore silently accepted. Native also aborts there, so parity probably holds. But the guard now protects less than before, and the only remaining protection is the event ID suffix and operation lookup. The lookup scans all functions by operation ID, and it assumes IDs are unique across functions.
**Fix:** Either narrow acceptance to the case where `LiveResources` contains only the fixture or file owner, or add a test with a non-owner live resource plus an add-overflow defect to pin the intended behavior.

## Info

### IN-01: Module-aware route list is duplicated by hand

**File:** `internal/compiler/check/check_modules_routes.go:11-13`
**Issue:** `ModuleAwareRoutes()` is a hardcoded list. The comment admits that `phase30ModuleRouteFunctions` and `phase30BoundedWant` in `session` duplicate it and are "cross-referenced by comment only". Drift is only caught if `TestPhase321ModuleAwareRoutes` or the route audit compares them. The usage text and the `module.imports_not_loaded` message now depend on a list nothing derives from the actual dispatch.
**Fix:** Confirm that one test fails when a command is added to the dispatch but not to the list. If none does, add one.

### IN-02: Brittle `"n:"` substring check in the CLI test

**File:** `cmd/schway/main_phase321_run_input_test.go:31`
**Issue:** `strings.Contains(stdout+stderr, "n:")` is meant to prove the parameter name `n` is not echoed. It matches any `n:` in future output text, for example "version:" in a prose message. It also misses a parameter named something other than `n`, so the check is both flaky and weak.
**Fix:** Assert the exact expected JSON diagnostic message and the absence of `dir`. Alternatively, use a fixture with a distinctive parameter name such as `zq_param_marker` and check for that.

### IN-03: Hardcoded `64` digest length and repeated `git ls-tree` magic in `codedigest.sh`

**File:** `scripts/codedigest.sh:31-35`
**Issue:** The post-check hardcodes `64`. The exclusion of `.md` files lives in two places: `grep -v '\.md$'` here and `':(exclude)*.md'` in the freeze script. Both are correct today, but they must change together.
**Fix:** Add a comment in both scripts cross-referencing the other, or add a test that compares the two exclusion rules.
