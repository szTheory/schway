## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| living docs -> readers | a doc can claim hosted evidence for code the receipt does not bind | evidence claims (integrity) |
| user source file -> CLI output | the refusal must not reflect file content, paths or identifiers | file paths, parameter names (low) |
| exit class -> scripts/CI | a misclassified exit hides a real tool failure | process exit codes (integrity) |
| user source -> checker -> cgen | a shape the checker admits but no engine lowers produces ill-formed C | generated C (integrity) |
| interpreter oracle -> differential verdict | an over-wide predicate would hide a real leak on a normal return | defect verdicts (integrity) |
| primary path -> independent peer | a peer that consumes the primary result cannot detect its bugs | execution-tier classification (integrity) |
| receipt scripts -> evidence claims | a gate that computes the wrong digest or ignores a claim lets a stale receipt stand | codedigest, receipt markers (integrity) |
| import-bearing source -> single-file route | a route that silently ignores imports would analyse the wrong program | module graph (integrity) |
| planning records -> auditors | a disposition can claim a fix no test witnesses | review dispositions (integrity) |
| local tree -> hosted receipt | a code change after the freeze would make the receipt bind different code | FREEZE_COMMIT / FREEZE_DIGEST (integrity) |
| agent -> remote repository | push and dispatch act on shared state with the user's credentials | git push, workflow dispatch (privileged) |
| downloaded artifact -> repository | hosted logs are untrusted bytes until gated | CI log artifacts (untrusted) |
