<objective>
Make a foreign nonlocal exit impossible to miss: one process-root landing pad, a static-storage ledger, leak events emitted for every acquisition still live, a defect termination — and an allowlist over the linked binary's undefined symbols that fails until a human audits each new one.

Purpose: ROADMAP success criterion 3's second half says a foreign nonlocal exit cannot *silently* bypass Lang cleanup. Prevention against opaque C is unachievable and claiming it would be an unproven promise; detection is achievable and this plan delivers it, while prevention is delivered statically at the declaration layer by plan 01's mandatory policy refusal.
Output: the landing pad and ledger in generated C, a second frozen foreign translation unit that performs the nonlocal exit so the pad has a reachable witness, the undefined-symbol allowlist control with its honest tool-missing status, and interpreter-versus-native agreement on the leak events.
</objective>

<flagged_assumptions>
The edge probe left **FFI-01** and **RES-01** `unresolved` (`category: unclassified`).

- **FFI-01 — unresolved by the probe.** Assumed instead: the unwind edge that is actually checkable is "did anything link into this binary undefined that a human has not audited", not "does this binary contain an unwind section". The section reading was measured on this host and rejected because the platform mandates compact unwind for many function shapes regardless of the compile flags, so a section assertion would pass or fail for the wrong reason. If FFI-01 requires a direct proof that no unwind can cross the boundary rather than an audit of what crosses it, this phase does not deliver that and CONTEXT.md judges it unachievable against opaque C.
- **RES-01 — unresolved by the probe.** Assumed instead: on the nonlocal-exit path the correct behavior is to *report* every still-live acquisition as leaked and terminate, not to release it. A release from that state is undefined behavior, so RES-01's "release exactly once" is read as scoped to the return and typed-failure paths, with the nonlocal-exit path producing an honest leak report instead. If RES-01 is read as requiring cleanup on every path including this one, it cannot be satisfied without introducing the use-after-free D-04-18 exists to prevent, and that conflict should be escalated rather than resolved in code.
</flagged_assumptions>
