<design_decision id="DD-04-13-01" title="Full C-identifier shape, not comment-safety only, for the three policy values">
The verification report's `missing:` item 1 offered "C-identifier-shape (or
minimally comment-terminator-forbidding)". **Decision: full C-identifier shape
(`^[A-Za-z_][A-Za-z0-9_]*$`) for `Allocator`, `Unwind` and `NonlocalExit`** —
the same predicate 04-12 applied to `Symbol`.

Justified against the real in-repo values, enumerated before deciding. Every
`allocator:`, `unwind:` and `nonlocal_exit:` value anywhere in the repository is
a bare C identifier:

| Value | Where |
|---|---|
| `forbidden` | `unwind:` and `nonlocal_exit:` in all ten `testdata/phase4/*.lang` fixtures, seven `internal/compiler/native/native_test.go` sources, `internal/compiler/check/check_test.go:1607-1608`, `internal/compiler/session/session_test.go:564-565` |
| `possible` | `nonlocal_exit:` in `testdata/phase4/nonlocal_exit_probe.lang:38` and `native_test.go:192` |
| `libc_malloc` | every `allocator:` in every fixture and test source, and `internal/compiler/session/session.go:532`'s constructed contract |
| `a_different_allocator` | `internal/compiler/cgen/cgen_test.go:148`'s mutation-sensitivity assertion |

None contains a space, hyphen, dot or any other non-identifier byte, so the
identifier rule **rejects nothing that is accepted today** and is therefore not
a breaking change to any existing source, fixture, golden or test. It is chosen
over comment-safety-only because comment-safety is context-specific: these same
values are also serialized into the sidecar manifest JSON and are candidates for
future non-comment splices, and a rule that admits
`libc malloc; extern void x();` merely because it lacks `*/` would leave a
second injection open the moment any emitter stops wrapping them in a comment.
Identifier shape is also the consistent contract: `Symbol` already carries it.

One consequence stated plainly rather than discovered by the executor: an EMPTY
`Allocator` newly refuses, because `validCIdentifier("")` is false and no
existing check requires `Allocator` to be non-empty. Evidenced above: every
foreign block in the repository declares an `allocator:`, so no accepted program
is affected, and an absent allocator identity is already a violation of FFI-01's
own "allocator identity" obligation. `Unwind`/`NonlocalExit` emptiness is NOT
affected, because the new check is deliberately placed AFTER the existing
`foreign.unwind_policy_undeclared` non-empty check, which keeps reporting its
own code for `testdata/phase4/foreign_unwind_undeclared.lang`.

For the REMAINING spliced string fields the identifier rule is wrong and is not
used: `Layout.Fields[].CType` is legitimately `unsigned char` (a space-separated
C type expression), and the obligation fields are prose-adjacent vocabularies.
Those get comment-safety plus a context-appropriate token shape instead — see
Task 3.

**Reversibility: `costly`, not `one-way`.** Per `planner-reversibility.md` and
the run's own rating instruction: a full-identifier choice is `one-way` only if
some legitimate in-repo policy value would newly be rejected. The table above
shows none is. What remains is that three new refusal-code strings enter a
shipped validator's and checker's observable output contract, and downstream
gate JSON or tooling may key on them — a small revert, no migration, no
persisted format change, no consumer outside this repository. No
`checkpoint:decision` is inserted.
</design_decision>
