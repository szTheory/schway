<objective>
Close 04-VERIFICATION.md gap 1 (04-REVIEW.md's new CR-01): stop
`checkReleaseOrder`'s independent rederivation from silently collapsing two
disagreeing acquisition histories that converge on an INTERIOR (non-terminal)
block, by collecting every `ok`-pattern edge per target block, independently
rederiving each candidate at a merge, and refusing disagreement with a new
`core.release_order_merge_mismatch` code — plus the falsifier that proves the
collapse was real and the companion that proves the fix does not over-refuse.

Purpose: D-04-07's own wording is that corevalidate "independently rederives...
and compares." Plan 04-08 made that true at TERMINAL blocks: the per-terminal
loop iterates all of `edgesByTo[block.ID]` (a slice) and requires the block's
one fixed release list to match what EVERY incoming edge rederives. The comment
above that loop states the principle plainly — what the rederivation cannot
tolerate is skipping the check for a merge point. But `rederive`'s own backward
hop through interior blocks reads `okEdgeInto`, a singular
`map[string]core.Edge` populated by `okEdgeInto[edge.ToBlockID] = edge`
(confirmed at corevalidate.go:1206 and :1210) and consulted as
`edge, ok := okEdgeInto[currentBlockID]` (confirmed at corevalidate.go:1265).
Two `ok` edges into the same interior block therefore leave only the last one
written; the other history is never rederived and never compared. When the KEPT
edge happens to agree with the terminal block's actual release list, a
hand-corrupted `core.Program` validates while a genuinely disagreeing declared
path was never examined. It is the same defect class one level removed, and it
is untested: `TestMergeTerminalBlockDivergentReleaseSetsRefused` and
`TestMergeTerminalBlockAgreeingChainsAccepted` both add their second edge into
the TERMINAL `success` block, never into an interior `step:N` block.

What this plan does NOT do: it does not touch the terminal-block loop 04-08
landed, does not touch the visited-set cycle guard 04-10 landed (it preserves
it, per-branch), does not add an acyclicity precheck to `blocksAndEdges`, does
not touch `edgesByTo`, and does not change `check.go` — check.go's honest
lowering cannot produce this shape today (each step has a single `ok`
successor, and a `discard`'s converging edges are `ok`/`err`, not two `ok`s), so
this is defense against an adversarial artifact, exactly what corevalidate is
for.

Output: the widened map, the per-candidate agreement check and its refusal in
`corevalidate.go`; two tests in `corevalidate_test.go`; one Mutation-Kill
Register row.
</objective>
