## Blocking constraints — these carry forward from Phase 02 unchanged

- **Native evidence must remain causally derived from executed C state.** Not restated,
  not re-derived from the source. The O0/O3 source-mutation control proves this and must
  keep firing.
- **Ownership test oracles must remain independently implemented.** WR-02 shipped because
  the "independent" oracle encoded the same wrong law as production. The Phase 3 path
  oracle and the validator's own liveness derivation must be mechanically different
  derivations, not shared helpers.
- **Every input and every spawned-process stream and time boundary must stay bounded.**
  Max-plus-one reads, independent stdout/stderr writers, explicit deadlines, counted work.
- **Generated C keeps one global ordinary-identifier namespace.** Collision handling
  preserves frozen names and goldens when no collision exists.
- **`.planning/milestone.lock` is orchestrator-owned.** Do not edit, commit, or delete it.

## Phase 03 constraints on top of those

- OWN-03 is **acyclic** (branch-only) this phase. Loop-carried loan liveness is Phase 4+.
- **`__LANG_` → `_LANG_` is 03-01's first standalone commit**, before any new C artifact
  is frozen (D-02-05). The cost only grows after that.
- **No `lang.core/2`.** New core fields are additive and `omitempty`. Phase 1 and Phase 2
  goldens stay byte-identical; 03-06 Task 3 asserts this key-by-key as parsed JSON.
- **A new `OperationKind` must be updated at four sites** — `check`, `corevalidate`,
  `interp`, `cgen` (D-12a). Miss one and the operation silently vanishes from the trace
  the O0/O3 differential compares, which is a self-confirming pass.

## Standing process rules (adopted after Phase 02's three gate failures)

All three failures shared one shape: **a green test whose reachable input space did not
contain the hard case.** Coverage was never the problem.

1. A differential is not evidence until reverting the production hunk makes it fail.
   Mutation-kill every oracle.
2. Ask what inputs a green property test actually reaches before trusting it, and write
   the unreachable shapes down.
3. Drive behaviour through the shipped binary on hand-written programs, not only through
   the gate's own corpus — the gate only ever sees what ships with it.
