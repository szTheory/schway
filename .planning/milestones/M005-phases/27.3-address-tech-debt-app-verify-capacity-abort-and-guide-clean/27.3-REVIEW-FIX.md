### IN-01: Re-run path recompiles per input

**Files modified:** `internal/compiler/session/session_app_verify.go`
**Commit:** cd08945
**Applied fix:** Took the review's "document the cost" option. A doc comment on `runAppVerifyLevel` records the following:
- `BuildCache` is nil and `native.Runner.Run` compiles on every call. After a batch capacity failure, the level therefore costs n+1 clang compiles and n extra timeout budgets.
- The cost is paid only after the named capacity code.
- Cases are capped at `MaxReplayCaseCount` (16).
- Reusing one binary would need a new `native.Runner` API.

Caching was not attempted. It would mean changing the native API and the runner's build semantics, which is more than an Info finding warrants.

### IN-02: Capacity guard is only partially converted

**Files modified:** `internal/compiler/cgen/cgen.go`
**Commit:** fab8ef4
**Applied fix:** Added a Go comment above the recorder variants in `emitEventSupportSchema2`. The emitted C text is unchanged. Converting the other variants would change emitted C and the accepted-corpus hashes. The comment explains why each remaining path is safe:
- **Application-shell variants:** they report overflow through `schway_event_overflow`, which becomes the `lang.app-capture/1` `capacity_exhausted` status.
- **Non-tracked execution variant:** it is selected only when `hasCyclicScalarCopy` is false. In that case each activation records at most its static operation count, and `invocationEventCapacity` sums exactly that count over the bounded unfolding. The guard is therefore unreachable for admitted programs. If it were ever reached, `return 0` makes every call site `abort()`. That fails closed and is never reported as a pass or as the capacity code.
- **`occurrence == UINT64_MAX` check:** `occurrence` is bounded by `schway_event_count`, which is below the static capacity, so the check is unreachable. It would also fail closed through the same `abort()`.

Reviewer note: the claim that the non-tracked guard is unreachable rests on `invocationEventCapacity` and `hasCyclicScalarCopy`. No test proves it directly. The fail-closed `abort()` behavior is visible in the emitted call sites (`cgen_program.go`, the `if (!schway_record_event(...)) abort();` lines).
