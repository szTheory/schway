## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| pre-fix baseline -> post-fix comparison | the golden is the only evidence that accepted programs keep their bytes; it must come from the pre-fix revision | core and C hashes of the accepted corpus |
| test harness -> evidence record | red runs must be real executions, not reconstructed text | test command, exit code, output |
| checker output -> independent peers | corevalidate and originvalidate are the trust boundary; producer output must fit them, never the reverse | core programs |
| admitted core -> cgen scalar emitter | the scalar emitter has no release, loan or foreign-call semantics; only pure scalar bodies may reach it | admitted core functions |
| emitted C -> clang | generated C must compile under the project's warning flags without masking real defects | generated C17 |
| local branch -> public origin / hosted CI | push and dispatch are outward-facing; human-authorized only | commits, workflow dispatch |
| hosted run record -> evidence prose | claims must match what was observed | run IDs, job conclusions, SHAs |
| planning docs -> hosted meta-tests | a malformed planning doc can fail the hosted run | planning markdown |
