# Phase 27.2: Code Review Report

**Reviewed:** 2026-10-10
**Depth:** standard
**Files Reviewed:** 9

## Summary

The checker split in `scalar.go` is sound. It fires only when `b.current == 0` and block 0 is not terminated, so programs with if/while keep their shape. The cgen classifier clause is conservative: it excludes Match, foreign, loan, non-U64 and any op outside the Const/Copy/Return/Write set. The negative cgen tests exercise both exclusion paths. One byte-identity gap exists in the `(void)param;` emission (WR-01). It is not covered by the golden corpus.

## Warnings

### WR-01: `(void)param;` also changes C output for previously accepted programs

**File:** `internal/compiler/cgen/cgen_program.go:2642-2651`
**Issue:** The marker is emitted whenever no op reads the parameter. It is not limited to the newly admitted straight-line bodies. Previously accepted scalar programs that never read their parameter still go through `emitProgramScalarFunction`. An example is `fn main(n: U64) -> U64 { var t = 0 ... while t < 3 {...} t }`. Those programs now get an extra `(void)schway_scalar_0;` line, so their emitted C and EmitApplication hash change. This contradicts the "already-accepted programs stay byte-identical" constraint. The golden test passes only because no corpus file has an unread parameter. The guard has a blind spot, and any such program would fail it. The `parameterRead` scan also looks only at `SourceID` and `RightID`, so it is coupled to the operand-field set by hand. A future operand field would silently produce a stray marker or a missing one.
**Fix:** Gate the marker on the new classifier path, so the old path keeps its exact bytes:
```go
if !parameterRead && isStraightLineScalarBody(function) {
    fmt.Fprintf(out, "  (void)%s;\n", locals[parameter.ID])
}
```
Alternatively, add a corpus witness with an unread parameter and an if/while body to the identity test. Then decide explicitly whether the byte change is acceptable.

## Info

### IN-01: Brittle hard-coded generated block ID in test

**File:** `internal/compiler/check/check_test.go` (`TestPhase272BranchFreeBodyReturnBlockSplit`, `returnID := main.ID+":block:return:1"`)
**Issue:** The test hard-codes the `newBlock` naming counter (`return:1`). A change to ID allocation will fail the test even though the CFG shape is correct.
**Fix:** Assert on `linear.Blocks[1].ID` having the `:block:return` prefix, and derive `returnID` from it.

### IN-02: `Bool` place allowance in the classifier is unreachable

**File:** `internal/compiler/cgen/cgen_program.go:2538-2542`
**Issue:** `isStraightLineScalarBody` permits `Bool` places. The allowed op set contains no comparison or branch op, so a Bool place cannot be produced by any admitted op. This is dead permissiveness that widens the accepted set for hand-built programs. Peer classifiers also drift by design (see the comment above `hasScalarOperations`).
**Fix:** Restrict the allowed place types to `U64`, or add a comment explaining why `Bool` is tolerated.
