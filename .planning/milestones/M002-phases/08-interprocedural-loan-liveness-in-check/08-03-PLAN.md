**Pattern A (`ReturnsBorrowOfParam`), caller body in both members:**
`let borrowed = borrow buffer` / `let aliased = escortee(borrowed)` /
`let delivered = take buffer` / `aliased`. The two members differ in exactly one
token region — the callee's declared return type:
  - `twin_a_refuse.lang`: `fn escortee(buffer: Buffer) -> borrow(buffer) Buffer`
    (a declared shared borrow of the parameter → `ReturnContract.Mode == "shared"`).
  - `twin_a_accept.lang`: `fn escortee(buffer: Buffer) -> Buffer` with an owned
    body (`let taken = take buffer` / `taken`) → `ReturnContract.Mode == "owned"`.
Reuse the existing borrow/take binding grammar unchanged; read
`testdata/phase3/public_view.lang` first and do not invent syntax.

**Pattern B (`UsesParam`), caller body in both members:**
`let borrowed = borrow buffer` / `let delivered = take buffer` /
`let observed = probe(borrowed)` / `observed` — the `borrow; move; call` order.
Both members declare `fn probe(buffer: Buffer) -> Buffer` identically; they
differ only in `probe`'s BODY: the refusing member reads the parameter
(`let seen = borrow buffer` before returning an owned value), the accepting
member never touches it. Record in each fixture header that `ParameterContract.Mode`
is `"owned"` for every function the grammar can express today, which is precisely
why `UsesParam` must be body-derived and cannot come from a declared field
(D-08-01).

**Fixture headers.** Each fixture opens with a comment stating: which pattern it
belongs to, which member of the twin it is, the single thing that differs from
its twin, and the exact diagnostic code expected (or `no diagnostics`). Follow
`testdata/phase07/relay_escort_witness.lang`'s header depth — these headers are
the reviewer's evidence at the mid-phase gate.

**The harness.** Add `readPhase08Fixture` mirroring `readPhase07Fixture`, then
`TestInterproceduralTwinPairsDifferOnlyInTheCallee`: parse both members of each
pair, extract the CALLER function's `ast.LinearBody` from each, and assert the
two callers are structurally identical — same binding count, same per-binding
`RHS.Kind`, same `RHS.Source`/`RHS.Callee`/`RHS.Arguments`, same `Result`. A pair
whose callers differ fails this test, which is what stops a caller-varying pair

`leaf` declares a borrowed return of its parameter, `relay` forwards it
(`relay`'s own declared return borrows its parameter, and its body's result is
the call to `leaf`), and `caller` runs the Pattern A shape against `relay`.
`relay_depth2_accept.lang`: identical except `leaf` declares an owned return and
`relay` forwards an owned value. Add `TestInterproceduralLivenessRelayDepth2`
asserting refusal and acceptance respectively, AND asserting that `relay`'s own
derived summary entry — not `leaf`'s — is what the caller's admission consulted.

from "it happens to work for the one-hop case"; this is the direct generalization
of Phase 07's finding that a straight chain could not kill the highest-value
cycle mutation and diamonds were required.

**(b) Negative control (D-08-28.4).** `negative_control_fails.lang` and
`negative_control_infallible.lang`: two programs whose callees differ ONLY in
fields the liveness law must never consult — the callee's `Fails` vocabulary and
its `Foreign.*` reach. Both members must produce the SAME verdict as each other.
Add `TestInterproceduralLivenessNegativeControl` asserting verdict equality
between the two, and asserting that the two programs' derived summary entries for
the callee are equal field for field. This is the "which fields are NOT named"
half of criterion 4 and it is cheap; a corpus that only ever varies
liveness-relevant fields never demonstrates the law correctly ignores the rest.

**(c) Match-arm regression (D-08-28.5 — recommended, explicitly not
gate-blocking).** `match_arm_call.lang`: a match-bodied function calling the same
callee from both arms. Add `TestInterproceduralLivenessMatchArmRegression`

requirement: D-07-28's both-arms guard was about call-graph EDGE DISCOVERY, while
