**R-01 — the authoritative source of every `lang.interface/1` field.** codex is
correct that the surface language declares no parameter ownership: every
parameter is `name: Type` (`parser.go:245`, `:321`), and the only ownership-
bearing declaration in a signature today is the return annotation
`-> borrow(p) T` / `-> borrow mut(p) T`, already lowered to
`core.Function.PublicOrigin`. The distinction that resolves this: SEM-05 forbids
**a caller's admission path** from reading a callee body. It does **not** forbid
the **producer** from reading one — `BuildInterface` exists precisely to strip a
body into a summary, and `Abilities` is already derived that way today. Each
field's authority:

| `/1` field | Authority | Notes |
|---|---|---|
| `ParameterContract.ID`/`Name`/`Type` | `core.Function.Parameter` | verbatim |
| `ParameterContract.Mode` | the **declared parameter form** | the grammar has exactly one form today (by-value), so the total function is `"owned"`. A future `borrow` / `borrow mut` parameter form maps to `shared` / `exclusive`. Any other value is unreachable and is refused by `DecodeInterface`. |
| `ParameterContract.Drops` | producer-derived from the checked core | whether the callee discharges the drop obligation on its owned parameter. Producer-side body reading is legal; caller-side is not. Doc comment must say so. |
| `ReturnContract.Type` | `core.Function.ReturnType` | verbatim |
| `ReturnContract.Mode`/`Paths` | `core.Function.PublicOrigin` | `nil` → `{Mode: "owned", Paths: []}`; `Access: "shared"` → `{shared, Paths}`; `"exclusive"` → `{exclusive, Paths}`. `Paths` empty **iff** `Mode == "owned"` (D-07-09). |
| `ReturnContract.Fresh` | producer-derived | true iff `Mode == "owned"` and the returned type carries the `drop` ability, i.e. the caller inherits a new drop obligation |
| `Abilities` | the existing `function.ID+":type:0"` type-fact lookup | `originvalidate.go:427` — the site whose silent empty-abilities fallback is `07-02`'s seeded fault 1 |
| `Callable` | **defined in `07-02-PLAN.md`** (D-07-31/D-07-32) | this plan declares the field and leaves it at its fail-closed zero value `false`; it does **not** invent a derivation |
| `Fails` | `core.ForeignContract.Fails` vocabulary, reused verbatim | `""` = infallible; no new failure vocabulary is minted |
| `Foreign` | `core.ForeignContract`, closure-derived worst case | plain strings per the `core.go:60-64` precedent (planner discretion, exercised) |
| `ClosureDigest` | D-07-37's canonical preimage | Task 3 |

**R-02 — the protocol projection is deliberately lossy, and says so.**
`protocol.InterfaceSummary` / `InterfaceFunctionAnswer` stay a *command answer*,
not a second copy of the `/1` artifact. Reason: `protocol` is a separate
versioned surface, and mirroring `/1` there would create a second schema that can
drift from the first with no producer forcing them together. The projection gains
only what a body-blind CLI consumer can act on today. Its doc comment must state
that it is a lossy projection and that `core.Interface` is the artifact of record.
</planner_resolutions>
