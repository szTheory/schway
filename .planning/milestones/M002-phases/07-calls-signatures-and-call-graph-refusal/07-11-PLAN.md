<language_surface_constraint>
No arithmetic, no iteration, no collections, no strings, no numeric type beyond
`Byte`; `match` is the only control flow. Fixtures use only `module`,
`export { fn ... }`, `data`, `fn f(p: T) -> T`,
`let x = borrow y | borrow mut y | take y | g(x)`, and `match`. Calls are
A-normal form (D-07-01): arity exactly 1, and the argument is the NAME of an
in-scope binding, never a nested expression — so there is **no `f(take y)`
syntax** and no way to mark a call-site transfer explicitly in source today.
Only `Byte` and `Buffer` are executable shapes (`check.executableShape`):
`Byte` grants `core.AbilityCopy`, `Buffer` does NOT
(`ability.go:144-155`, "a shareable, noncopyable resource"). Every function's
declared return type equals its declared parameter type (`sameType`), and each
function therefore carries exactly ONE type fact, `<functionID>:type:0`.

Two consequences the executor must not re-derive under pressure:

1. Because there is no `f(take y)` syntax, "refuse a non-copyable call
   argument outright" would make `Buffer` **unpassable**, which would change
   `call_uncallable_callee.lang`'s reported code and would refuse
   `relay_escort_witness.lang` — a fixture this phase forbids disturbing. The
   checkpoint below ratifies consume-on-call instead, for exactly that reason.
2. The `ownership.use_after_move` diagnostic and its ordered causes ALREADY
   exist at the top of `resolveCallBinding` (check.go:1844-1852). This plan
   mints **no new diagnostic code string on the `check` side**; it makes an
   existing gate reachable by recording the move that must precede it.
</language_surface_constraint>

<assumption_delta_decision>
`gsd_run query assumption-delta scan "07" --json` returned `detected: true`
(signals: `pluralization`). The honest delta in this plan is a
`derived → chosen` anchor move, recorded rather than dismissed.

- **Noun that is now primary:** the **binding kind's ownership effect** is a
  property of every binding kind including `call`, not a property of the
  binding-switch's five arms. Previously the switch WAS the law's domain, and
  `call` sat outside it by construction (`continue` before the switch).
- **Decision: `promote`.** The ownership law is promoted to apply at every
  place a `core.Place` is produced from another place, including inside
  `resolveCallBinding`; the binding switch is demoted from "the law" to "one of
  two sites that apply it". This is a promote, not an add-alongside: no
  construct retains an exemption.
- **Consequence recorded:** because the law now lives in two code sites, the two
  must not drift. Task 1 asserts the consume rule is expressed ONCE, inside the
  shared `resolveCallBinding`, so both call paths (`analyzeStraightLine`,
  `analyzeArmBody`) get it from one expression rather than two copies.
- **What would force further change:** arity-N (D-07-07). With two arguments,
  consumption becomes an argument-ALIASING question (two arguments naming the
  same place; one shared and one exclusive loan of one owner), which is a
  genuinely different rule and is exactly what D-07-07 defers. Task 3's
  corrected D-07-07 says so in those words.
</assumption_delta_decision>

  <name>Checkpoint: ratify consume-on-call as the call-site ownership semantics</name>
  <decision>
07-REVIEW.md CR-01 offers two readings of call-by-value and asks for one to be
chosen. The choice is a permanent language-semantics decision, it decides which
programs the compiler accepts forever, and it interacts with a fixture this
phase forbids disturbing. It is ratified here, before any code is written.

**The two readings.**

**(A) Consume-on-call — PROPOSED DEFAULT.** A call transfers its argument.
Consumption is decided by the ARGUMENT TYPE's `core.AbilityCopy`, exactly as
the binding switch's default arm decides today:
- copyable argument (`Byte`) → the call COPIES it; the caller's binding stays
  live and may be passed again;
- non-copyable argument (`Buffer`) → the call MOVES it; the caller's binding is
  marked `initialized = false` with `movedAt` / `moveTargetID` /
  `moveTargetName` recorded, and any later use — including a second call — is
  refused by the EXISTING `ownership.use_after_move` gate already sitting at the
  top of `resolveCallBinding`.

  Consequences, stated: **no existing fixture changes verdict.**
  `call_uncallable_callee.lang` consumes its `Buffer` once and still reports
  `core.callee_not_callable`. `relay_escort_witness.lang` consumes its
  `borrow mut` binding once and never uses it again, so it still checks clean
  and the deferred D-03-02 divergence is untouched. CR-01's program is refused
  with `ownership.use_after_move`. **No new `check`-side diagnostic code string
  is minted.**

**(B) Strict parity with the binding switch — refuse outright.** A non-copyable
call argument is refused with `ownership.transfer_requires_take` ("noncopyable
binding requires explicit take"), exactly as a plain non-copyable binding is.

  Consequences, stated: because A-normal form has **no `f(take y)` syntax**
  (D-07-01: the argument must be the NAME of an in-scope binding), there is no
  way to satisfy the requirement, so `Buffer` becomes **unpassable to any

  gap-closure's scope.
