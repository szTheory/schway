<objective>
Make `lang explain`'s cause DAG name the function each cause step belongs to, and
fix the containment bug that silently manufactures `narrows` edges across function
boundaries.

Purpose: DX-05. An agent reading a cross-function cause chain currently cannot tell
which function a step is in, and — worse — `explainSpanStrictlyContains` is pure
byte containment, so a node whose span is a whole function declaration becomes the
narrowest containing ancestor of every subsequent cause anywhere in that body,
asserting a containment relation the rule was never written to mean once causes
cross functions. That is a derivation bug, not a display bug (D-13-19).

Output: two additive `ExplainNode` fields, an `ExplainFunction` table on
`ExplainSummary`, peer-re-derived function resolution, the function-scope `narrows`
guard with its mutation-kill seam, and a recorded observation deciding the
`lang.explain/0` -> `/1` question.

**Discretion settled by the planner, recorded here:** flat `function_id` +
`function_name` fields (not a nested object, not SARIF's `fully_qualified_name` —
that matters only once M003 modules add a namespace segment); the `functions` table
on `ExplainSummary` SHIPS NOW because repair targeting needs whole-function spans;
`ExplainDefaultDepth` stays 3, since the cross-function depth risk is a
default-value question with an existing `--depth` escape hatch (D-13-21); a cause
in foreign-C boundary territory has no Lang function and OMITS the field entirely
rather than introducing a sentinel kind.
</objective>
