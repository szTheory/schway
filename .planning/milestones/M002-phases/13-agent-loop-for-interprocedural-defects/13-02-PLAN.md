<objective>
Ship the contract-boundary blame rule: blame the party that violated its own
declared signature, with the detection site demoted to a typed secondary — and
make its fail-open failure mode structurally impossible.

Purpose: this is the phase's riskiest assumption (ROADMAP: "blame lands on the
function that violated its own declared contract, rather than on the function
where the error was detected"). D-13-07 is what separates this from a heuristic:
without a compile-time exhaustiveness guard and an explicit `blame_undetermined`
route, a missed B1 case silently becomes caller-blame and a caller-side repair can
mask a broken callee contract while turning the check green.

Output: the B1/B2/B3 resolver, the `blame_undetermined` outcome, the shared
callee-before-caller helper, and the empirical proof that adopting the rule moves
zero Primary spans today.

**Planner assumption, surfaced not dropped:** the edge-coverage probe classified
DX-06 as `unclassified` — no generic edge category (adjacency / empty / encoding /
ordering) resolves it. It remains UNRESOLVED. The planner's explicit assumption is
that DX-06's edge behavior is fully pinned by D-13-03's three named branches plus
D-13-07's undetermined route, and by nothing else. If execution finds an
interprocedural cause that is neither a use fact nor a declared fact, that is a
fourth case the rule does not cover — escalate rather than widen B2.
</objective>
