## Planner findings the executor must not re-derive

- **D-09-50, verified at planning time.** D-09-23 prescribes feeding the
  synthetic shapes into `session_peer_gate_test.go`'s corpus gate. That is not
  achievable: package `check` exports exactly one admission entry point,
  `check.Program(program ast.Program) Result` (`check.go:46`), so no package
  outside `check` can compute a `check`-side verdict for a synthetically
  constructed `core.Program` — and the synthetic corpus is deliberately built
  against `core`'s types and never parsed (D-08-34), so there is no
  `ast.Program` to feed. The synthetic differential therefore lives INSIDE
  package `check`, which alone can reach both the unexported post-assembly pass
  and `corevalidate.Validate` (`check_test.go:20` already imports it). The
  `.lang` corpus gate stays exactly where it is.
- **This is a split of vehicle, never of truth.** `peerDivergenceExpected`'s
  two-directional exactness discipline is the definition of divergence in this
  tree, and the synthetic differential must reuse it by construction and
  cross-reference it by name.
- **`corevalidate_cycle_peer_test.go` already builds the shapes.**
  `syntheticProgram(edges map[string][]string)` (`:35`) takes a general edge map,
  so self-cycles, mutual cycles, and indirect 3+-hop cycles are all already
  constructible — `TestCyclePeerRefusesSyntheticMutualCycle` (`:156`) and
  `TestCyclePeerRefusesSelfEdge` (`:174`) are the shapes to extend, not replace.
- **`corevalidate_cycle_peer_test.go` has its own import guard**
  (`TestCyclePeerTestFileImportsStayIndependent`, `:137`) scanning that one file's
  own imports. Adding a `check` import to it would fire that guard. The
  `check`-side half of the cycle agreement therefore belongs in package `check`'s
  new differential file, not in the cycle-peer file.
