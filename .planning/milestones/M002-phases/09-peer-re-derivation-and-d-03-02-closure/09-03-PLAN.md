## Planner findings the executor must not re-derive

- **The fear was larger than the work.** `peerReturnDerivesFromBorrow`
  (`corevalidate.go:2099`) is ALREADY a forward set-propagation walk with
  `paramTrace` and `derived` maps. It tracks presence only
  (`derived map[string]bool`) — never access mode, never paths. The extension is
  an **access-mode payload on an existing walk**, not a file-sized duplicate of
  `originvalidate.go` (D-09-17).
- **Arity 1 collapses one of the three classes.** Because arity is 1,
  `PublicOrigin.Paths` has exactly one possible value (`function.Parameter.Name`)
  whenever any origin is derivable at all — so "understatement of paths"
  degenerates to a boolean the peer already computes. The genuinely new
  derivation work is **access mode** (`shared` / `exclusive`), not path
  containment. Re-open the moment arity widens past 1 (D-07-07, D-09-18).
- **The peer must differ from BOTH `check` and `originvalidate`.**
  `originvalidate` is itself already a third layer. The peer compares its
  DECLARED origin against its OWN forward-derived facts — a containment /
  refinement check — rather than re-implementing a backward combination law
  (D-09-19).
- **`PublishProblemsFor`'s exact four-class order** is: foreign-origin-omitted
  first (early return), then `core.origin_omitted` when `PublicOrigin == nil`,
  then a declared-access domain check emitting `core.origin_access_mismatch`,
  then `core.origin_understated` on path non-containment, then
  `core.origin_access_mismatch` on access disagreement
  (`originvalidate.go:357-395`). The peer must reach the same VERDICT; it is
  under no obligation to reach it in the same order, and must not copy the order
  as if it were the law.
