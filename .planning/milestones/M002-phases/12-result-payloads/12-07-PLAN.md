<objective>
Close CR-01's engine-layer half: collapse two independently-reimplemented
ambiguous derivations into one shared, ambiguity-detecting derivation, and stop
the D-12-38 fault-injection seam from being able to pass vacuously.

Purpose: plan 12-06 refuses the colliding shape at the source boundary, which is
the primary closure. But two copies of a now-"fixed" derivation is exactly the
divergence this project's convergence discipline forbids, and D-12-25 states the
governing principle directly: layout is ONE shared derived fact, not three
independent derivations. "Which alternative does this operation belong to" is the
same kind of fact, and it is currently derived twice — three times counting
IN-01's local detail lookup — each time by an ambiguous first-match linear scan.
`check`'s refusal also only governs programs that crossed the parser;
`session.PayloadProbeDataType` proves a `core.DataType` can be assembled directly
in Go and reach the engines without ever meeting `check`.

Separately, WR-02: the seam backing `TestPayloadSlotSwapMutationKilled` silently
falls back to the CORRECT write when no mismatch target exists, with no assertion
anywhere catching it. That is an anti-vacuity hole in a control this phase relies
on — the same defect class as CR-01 — and it is fixed in the same pass.

Output: `core.AlternativeNameForPayloadType`, `core.LookupAlternativeDetail`,
both engine copies deleted, a control proving they cannot return, and an
injection-applied assertion in the slot-swap control.
</objective>
