<objective>
Expand the groundedness lint from the tracer slice into its full shape: scope by
illocutionary role rather than filename, execute grep-shaped verification
commands, detect and pin per-branch groundedness, install corpus floors so the
lint cannot go inert by finding nothing, and cross-check the static test index
against the toolchain's own listing.

Purpose: the tracer proved the path. This plan closes the three ways the lint
could still be quietly useless — it could watch the wrong files, it could watch
only one of the two known ways a command silently stops verifying, or its glob
could stop matching and it would report a clean green over an empty corpus.

Output: one extended test file, a re-measured frontier pin, and a recorded R2b
finding set carried forward to the milestone's reconciliation phase.
</objective>

Add the two remaining classifications to the lint.

**Grep groundedness.** For a grep-shaped command with no pipe, redirect,
conjunction, semicolon or command substitution and a literal existing file
operand, execute it directly — argv form through `os/exec`, **never** through a
shell — and require at least one match. Zero matches is a finding. This is the
archival-breakage class: a grep over a path that moved during archiving keeps
exiting the same way while proving nothing, and it is one of the two known ways a
verification command silently stops verifying, so excluding it would leave the
lint watching only half the problem. Commands carrying any of the listed
metacharacters are classified by shape and handled under the runnability rule
instead of being executed — this argv-only, metacharacter-free restriction is a
hard implementation constraint, not a documentation note, because the command
text comes out of a document.

**Per-branch groundedness.** Split the run pattern's first segment on top-level
alternation and require **every** branch to resolve to at least one name. Apply
the markdown-unescape ruling from plan 14-01 before splitting, and record that
ruling again here in the finding messages, because the alternative reading
produces a very different finding count and the difference is otherwise invisible.

**Ship per-branch as detected and pinned, not enforced to zero** (D-14-16). This
is a deliberate sizing decision recorded in writing rather than taken silently:
re-adjudicating what each under-scoped row was *meant* to prove is judgment work,
not mechanical work, and folding it in here would push the phase past its sizing.
Per-branch findings enter the pinned frontier with their own classification and
are handed to the milestone's later reconciliation. The runnability, groundedness
and grep classes remain the ones this phase drives to zero, in plan 14-10.

Write the `<behavior>` cases as failing tests first, using synthetic documents and

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `.planning/**` command text → subprocess execution | Document-supplied command text is executed for the grep class; this is the only place the lint runs anything |
| document basename → enforced scope | A filename is attacker-controllable in the sense that a contributor can rename a file to change its scope |
| static test index → toolchain listing | Two independent derivations of the same set, neither trusted from the other |
