<objective>
Build criterion 3's cost gate: a synthetic call-graph corpus in four shapes, a
fitted growth exponent against operation count with a ratio-stability tripwire,
both hardcoded gate chokepoints widened together, and a ratified `hard` row in
the QLT-02 feedback-budget manifest with its own risk lane.

Purpose: this gate catches the phase's riskiest assumption — that a
signature-mediated fixpoint stays a bounded, summary-based analysis rather than
becoming whole-program borrow inference in disguise. Whole-program inference does
not fail a correctness test; it fails a cost curve.

And the correction that decides this plan's shape: **two independent places
hardcode the literal metric name that gates anything at all.** Any newly-named
metric is silently demoted to `observed` and produces a control that can never
block, while a reviewer reading only the manifest JSON sees `"gate_type": "hard"`
and concludes the gate is live. Widening both, with the promotion-passthrough
guard re-derived, is a named task here — not a free consequence of adding a row.

Output: `costcorpus_test.go`, two widened chokepoints, one manifest row, one lane.
</objective>

## Planner assumptions (unresolved edge probes)

**EFF-02 / boundary — resolved by CONTEXT** and lifted into `must_haves.truths`:
exponent fitted against operation count, bounded at ≤ 1.2, plus the ≤ 15%
ratio-stability tripwire.

**EFF-02 / precision — PLANNER ASSUMPTION owned by this plan, made concrete.**
`session.QLT02BudgetRow.ValueOrBound` is `int64`, so a fractional exponent cannot
be stored without a published-schema change — forbidden by D-08-24's reasoning
(a one-way schema change on research-only justification). The bound is therefore
stored in **milli-units**: `value_or_bound: 1200`, `unit: "milliexponent"`. The
gate compares `int64(math.Round(exponent*1000)) > 1200`. `math.Round` rounds half
away from zero; the ≤ 1.2 boundary stays inclusive; a fitted 1.2004 passes and a
fitted 1.2006 fails. **This tie-breaking contract is a planner decision, not a
CONTEXT lock**, and Task 1 must pin it with `TestGrowthExponentRoundingBoundary`.
