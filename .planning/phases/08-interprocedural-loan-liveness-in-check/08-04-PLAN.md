<objective>
Give the only genuinely iterative fixpoint in this phase a derived, auditable,
fail-closed bound with a named refusal; provoke that refusal through an
unexported seam so the control has been seen to fail; and harden the same
function's cycle pre-walk from native recursion to an explicit stack while
promoting its bare error string to a coded diagnostic.

Purpose: success criterion 2. And an honest framing that must survive into the
code, not just the plan — there is **no call-graph fixpoint to bound**. Reverse
postorder is one pass, summary derivation is two passes in program order; both
are bounded by construction. The intraprocedural worklist inside
`loanLivenessFixpoint` is the only iterative fixpoint, it already counts `work`,
and today it has no bound at all — it terminates purely by monotonicity over a
finite lattice. The bound is therefore an **internal-consistency assertion, not a
DoS defense**, and saying so plainly is what keeps it from being a magic number
nobody can audit.

Output: a derived bound, a named refusal, a seeded mutation-kill, an iterative
pre-walk, and a coded `check.cfg_back_edge`.
</objective>

## Planner assumptions (unresolved edge probes)

**OWN-06 / precision — PLANNER ASSUMPTION owned by this plan.** The bound is
computed in Go `int` arithmetic as a product of three terms. At the sizes this
language can express (`.planning/LANGUAGE-MATURITY.md`: 58 programs, ~28 lines,
one CFG block per match arm, arity 1) `blocks × loans` cannot approach
`math.MaxInt`, so **no overflow contract is specified and none is tested**. This
is an explicit assumption, not an omission: if a later milestone makes block or
loan counts program-controlled — iteration, loops, collections — this assumption
must be re-opened before the bound is trusted, and the executor must add a note
to that effect at the bound's declaration.

**OWN-06 / boundary — resolved by CONTEXT** and lifted into `must_haves.truths`
above (the derived bound and its named refusal).
