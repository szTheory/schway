<objective>
Close QLT-05: re-verify HDD reducer output on multi-function programs under
STRICT field equality from a cold start, close the silent-slippage hole in
`foreignCallSequenceFor` with a genuine second knower, and make the gate
non-vacuous by requiring a provably removable function.

Purpose: HDD's classic failure is slippage — reducing to a DIFFERENT bug while
passing re-verification clean. Two things make that possible here: a
multi-function foreign-call sequence that silently evaluates to `nil`, and
inheriting the search-time `CausalRole` relaxation at re-verification time. This
plan removes both.

Output: the widened and doubly-derived foreign-call sequence, the strict
re-verification lane and its `control:reduce.reverified` control, the anti-vacuity
gate fixture, and the phase's collected evidence-weakened claims.
</objective>

  <action>
Fix the silent-slippage hole at `session_phase5_mismatch.go:72-75`, where `foreignCallSequenceFor` returns `nil` for any multi-function program. Left as-is, the reducer could drop a call to a callee containing a foreign acquisition and drift-checking would compare `nil` to `nil`, see nothing, and reduce to a DIFFERENT bug while passing re-verification clean.

Knower 1 — static: widen the walk to cover EVERY function, visiting them in `callgraph.Order`'s reverse-postorder over the proven-acyclic call graph. `session` may import `callgraph` (its package doc, updated in plan 11-03, names `session` among the production consumers), so call it directly rather than re-deriving an order locally. The sequence is the ordered list of foreign acquisitions encountered across the whole program.

Knower 2 — dynamic: derive the SAME sequence independently from the `-O0` run's event stream, which already carries a `FunctionID` per event. This derivation must not call the static walk or share a helper with it beyond the event type itself; it reads the execution document, the static one reads the `core.Program`.

Compare the two and fail on disagreement with a named control. This is the "two independent knowers, never one derivation read twice" discipline applied to the one fact that guards against slippage — a single derivation here would leave the guard trusting itself.

Tests in `session_phase5_mismatch_test.go`:
- `TestForeignCallSequenceCoversAllFunctions`: on a multi-function program with a foreign acquisition in a NON-entry function, assert the static sequence is non-nil and contains that acquisition. Assert explicitly that it is not `nil` — the bug being fixed is a `nil` that looked like agreement.
- `TestForeignCallSequenceStaticAndDynamicAgree`: assert the two derivations produce equal sequences on the multi-function corpus.
- `TestForeignCallSequenceDetectsDroppedCallToForeignCallee`: construct a program, apply `drop-call-site` to the edge reaching the foreign-acquiring callee, and assert the sequence CHANGES. A sequence that does not move here is the slippage this fix exists to catch.
- `TestForeignCallSequenceSeededDisagreement`: perturb one derivation through a test-only seam and assert the comparison fails, proving the agreement check is load-bearing rather than trivially true.
