### Locked Decisions

#### Defects close the execution, ordinary completions close one frame

- **D-01:** Keep Go 1.24 standard-library/local implementation, existing core and execution schemas, direct calls, bounded frames and C17/Clang. Reuse mechanical wire/identity helpers where useful; independent peers must derive semantic facts themselves. No dependency or generalized exception/evidence system earns its cost here.
- **D-02:** Once a defect terminal has passed its existing operation, invocation, reason and outcome checks, close and mark every currently active invocation, in both legacy/static and dynamic identity modes. The interpreter already ends the whole frame stack on a defect; identity mode must not change that semantic rule. Preserve one-frame handling for ordinary return and child typed failure, so a caller can continue along its admitted error route. Do not invent caller unwind events, destructor calls or normal return values.
- **D-03:** Use checker-admitted source and actual interpreter traces for the CR-03 positives in both modes. Cover a legacy non-scalar callee and a scalar dynamic callee, nested returns, and a defect after earlier successful activations. Mutate the actual trace: wrong terminal attribution/reason/outcome, missing/duplicate terminal and a valid-looking caller event after the child defect must be refused. A repeated child event alone does not prove the callers were closed.

#### Dated CR-04 acceptance correction — 2026-10-16

- **D-04:** Replace the unsupported source-backed `OpReturn` demand with the real checked-source path: `foreign.failed` at an indexed `OpForeignCall`, followed by its generated error block's `OpFail`, including a child failure routed through the caller's error edge to its own terminal. ### Pattern 1: Defect terminals close the active execution

**What:** After existing operation, invocation, reason and outcome checks pass, mark the terminal invocation and every invocation on the live stack closed, then empty the stack. Keep ordinary function.returned and function.failed as a one-frame pop. [VERIFIED: internal/compiler/executionpeer/executionpeer.go:665-700; .planning/phases/37.1-close-gap-legacy-terminal-outcomes/37.1-CONTEXT.md:18-20]

**When to use:** Every execution-wide function.defected terminal in both legacy/static and dynamic scalar identity modes.

**Implementation shape (pseudocode):**

~~~go
if event.Kind == "function.defected" {
    for _, activation := range stack {
        closedActivations[activation] = true
    }
    stack = stack[:0]
} else {
    stack = stack[:len(stack)-1]
}
~~~

The exact event spelling is present in the peer terminal check as function.defected; the existing dynamic-only guard is i.dynamicCallIdentity && event.Kind == "function.defected". [VERIFIED: internal/compiler/executionpeer/executionpeer.go:676-700]

Add source-backed positives for a static/non-scalar callee and a scalar dynamic callee. Include a defect after earlier successful activations and mutate the real trace with bad source/type/reason/outcome, absent/duplicate terminal and a valid-looking caller event after the defect. Keep ordinary return and handled failure traces green. [VERIFIED: .planning/phases/37.1-close-gap-legacy-terminal-outcomes/37.1-CONTEXT.md:18-20]

### Pattern 2: Derive foreign failure meaning from indexed core facts

**What:** Classify a foreign failure only when its event ID maps to an OpForeignCall whose checked per-operation contract has Fails; independently check source/target places and compare the event’s failure constructor against the contract and relevant TypeFact.Shape.Constructor. Bind generated OpFail to the call’s ErrTargetID, ErrEdgeID, containing error block and same invocation. For a child call, bind the failure constructor to that callee’s derived failure set and the parent call’s declared error envelope/edge; do not accept an arbitrary matching type string. [VERIFIED: internal/compiler/core/core.go:227-241,633-665,900-919; internal/compiler/check/check.go:5441-5458; internal/compiler/corevalidate/corevalidate.go:1775-1783,2018-2049,2052-2109]

**When to use:** The actual checked examples/phase24/error.schway path, including the child failure that reaches a caller through its own error edge. The source declares these failure constructors verbatim, with line boundaries preserved: “data AcquireError =” / “| AcquireFailed”; “data UseError =” / “| UnsupportedByte”; “data ResourceError =” / “| AcquireFailed” / “| UnsupportedByte”. [VERIFIED: examples/phase24/error.schway:35-43]

**Observed refusal chain:** The current classifier handles function.failed for OpFail, but has no classifier branch for the foreign event; the actual foreign event is currently refused at unknown_kind. Once that event is admitted, OpFail terminal attribution compares the event’s constructor string to the core operation’s type-fact ID, which are different representations when a modeled failure is propagated. Add both exact foreign-event classification and constructor mapping; fixing only the terminal classifier is insufficient. ### Pattern 4: Emit reason bytes with an explicit length

**What:** Keep the raw reason value. For structured JSON, escape it at generator time and write the resulting JSON token with its byte count; for application stderr, write the fixed prefix, raw reason bytes, and newline through byte-counted output or an equivalent C-safe counted array. Preserve the existing ordinary printable path where that keeps frozen C identical. [VERIFIED: .planning/phases/37.1-close-gap-legacy-terminal-outcomes/37.1-CONTEXT.md:31-34; internal/compiler/cgen/cgen.go:740-756]

**Why:** C N1570 says a hexadecimal escape consumes the longest sequence of hexadecimal digits, fputs writes a null-terminated string without its terminating NUL, and fwrite takes an explicit element count. N1570 is the C11 committee draft; this citation supports those language/library details and is not a claim that a C17 draft was retrieved. [CITED: https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf, `6.4.4.4 ¶7, `7.21.7.4 ¶2, `7.21.8.2 ¶2]

The project’s existing schway_write_bytes(const char *data, size_t length) already uses fwrite(data, 1u, length, stream) and enforces output limits. Reuse it for the structured record; avoid schway_write_json_string(const char *value) for raw NUL-containing bytes because it iterates until '\\0'. [VERIFIED: internal/compiler/cgen/cgen.go:738-756]

**Important open boundary:** The lexer scans quoted text byte-by-byte and creates a string token without validating its interior as UTF-8, while the parser copies the interior bytes directly to DefectReason. The Go 1.24 encoding/json source says string values are coerced to valid UTF-8. Therefore, a malformed UTF-8 reason may be admitted yet cannot round-trip its original bytes through the current JSON string representation with encoding/json. The phase context prohibits source refusal and new wire fields; keep the required U+0001/NUL cases in scope, and make no all-byte claim until a bounded check establishes whether malformed UTF-8 is checker-admitted and how the existing wire contract treats it. [VERIFIED: internal/compiler/syntax/lexer.go:85-115; internal/compiler/syntax/parser.go:1376-1384; GOROOT/src/encoding/json/encode.go:49-53,228-232; .planning/phases/37.1-close-gap-legacy-terminal-outcomes/37.1-CONTEXT.md:31-34]

## Common Pitfalls

### Pitfall 1: Caller activity survives a child defect in static identity mode

**What goes wrong:** A valid-looking event from the caller after a child defect is accepted because only the child frame is popped in static mode.  
**Why it happens:** The all-stack closure is guarded by i.dynamicCallIdentity.  
**How to avoid:** On a validated whole-execution defect, close every invocation currently in stack and clear it in either identity mode; keep return/failure as a one-frame pop.  
**Warning signs:** The legacy-source mutation with a caller event after the child defect still passes. [VERIFIED: internal/compiler/executionpeer/executionpeer.go:665-700; .planning/phases/37.1-close-gap-legacy-terminal-outcomes/37.1-CONTEXT.md:18-20]

### Pitfall 2: The real foreign failure trace never reaches terminal checks

**What goes wrong:** foreign.failed is refused before the peer checks the generated OpFail.  
**Why it happens:** classify recognizes normalKind(OpForeignCall) == "foreign.called" but has no exact indexed foreign.failed case, yielding unknown_kind.  
**How to avoid:** Add a failure branch keyed to the indexed OpForeignCall event ID and its contract; then implement separate event attribution checks and OpFail constructor mapping.  
**Warning signs:** A test fails at unknown_kind for the original examples/phase24/error.schway trace. [VERIFIED: internal/compiler/executionpeer/executionpeer.go:526-529,720-745; examples/phase24/error.schway:7-24]

### Pitfall 3: Type ID representation mismatch blocks the admitted OpFail

**What goes wrong:** The event carries a constructor such as UseError, while the core operation’s TypeID is an opaque type-fact identifier; direct string equality rejects the actual trace.  
**Why it happens:** terminalOutcome emits modeledFailure.Type when present, but OpFail.TypeID still points at a TypeFact.  
**How to avoid:** Independently map TypeFact IDs to constructors, bind the foreign event to Foreign.Fails, bind the generated OpFail to its error target, and verify child constructors are in the caller’s exact error envelope.  
**Warning signs:** Replacing only the classifier changes the refusal from unknown_kind to terminal_attribution. [VERIFIED: internal/compiler/interp/interp.go:2234-2245; internal/compiler/executionpeer/executionpeer.go:665-674; internal/compiler/corevalidate/corevalidate.go:2018-2049,2052-2109]

### Pitfall 4: Handled child failure forces the wrong root outcome

**What goes wrong:** A child typed failure is treated as if it were already the execution’s terminal outcome, so the caller’s checked error branch cannot continue.  
**Why it happens:** A child OpFail can transfer its failure to the caller’s ErrTargetID and follow its ErrEdgeID; the caller’s own terminal decides the root outcome.  
**How to avoid:** Check typed-failure outcome kind only at a root terminal; keep child failure’s one-frame closure and continue the parent activation.  
**Warning signs:** A child UseError/AcquireError event causes the peer to reject the caller’s later event before its root terminal. [VERIFIED: internal/compiler/interp/interp.go:2843-2859; internal/compiler/executionpeer/executionpeer.go:676-700]

### Pitfall 5: Reason bytes differ between source, generated C and captured output

**What goes wrong:** A control byte can merge into a following C hex escape, and NUL truncates fputs/strlen output.  
**Why it happens:** C hexadecimal escapes consume the longest valid digit sequence; C string functions use a terminating NUL rather than source length.  
**How to avoid:** Emit raw app reason bytes with an explicit count and structured JSON with a safe serialized token plus explicit length. Keep output limits on structured capture.  
**Warning signs:** The reached probe’s U+0001+A, NUL+A or NUL+Z expected stderr bytes differ or truncate. [VERIFIED: .planning/phases/37.1-close-gap-legacy-terminal-outcomes/37.1-CONTEXT.md:31-34; internal/compiler/cgen/cgen.go:740-756; CITED: https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf, ``6.4.4.4, 7.21.7.4, 7.21.8.2]

### Pitfall 6: Compatibility comparator is weakened while output changes

**What goes wrong:** An amendment hides unrelated changes, wrong route, stale inputs or silently regenerates expected C from the post-fix emitter.  
**Why it happens:** Existing corpora compare a complete set of route outputs; a broad exception erases that evidence.  
**How to avoid:** Amend only measured rows, each bound to original source, checked core, route and old C; compare actual output to a reviewed explicit delta from the old bytes. Test missing, duplicate, extra, wrong-path, wrong-route, stale-binding and unrelated-byte controls.  
**Warning signs:** Any comparator accepts an unamended output difference or any emit_application row without an explicit measured reason. [VERIFIED: .planning/phases/37.1-close-gap-legacy-terminal-outcomes/37.1-CONTEXT.md:35-38; internal/compiler/session/session_phase36_prechange_test.go:533-593]
