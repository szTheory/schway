### Defects close the execution, ordinary completions close one frame

- **D-01:** Keep Go 1.24 standard-library/local implementation, existing core and execution schemas, direct calls, bounded frames and C17/Clang. Reuse mechanical wire/identity helpers where useful; independent peers must derive semantic facts themselves. No dependency or generalized exception/evidence system earns its cost here.
- **D-02:** Once a defect terminal has passed its existing operation, invocation, reason and outcome checks, close and mark every currently active invocation, in both legacy/static and dynamic identity modes. The interpreter already ends the whole frame stack on a defect; identity mode must not change that semantic rule. Preserve one-frame handling for ordinary return and child typed failure, so a caller can continue along its admitted error route. Do not invent caller unwind events, destructor calls or normal return values.
- **D-03:** Use checker-admitted source and actual interpreter traces for the CR-03 positives in both modes. Cover a legacy non-scalar callee and a scalar dynamic callee, nested returns, and a defect after earlier successful activations. Mutate the actual trace: wrong terminal attribution/reason/outcome, missing/duplicate terminal and a valid-looking caller event after the child defect must be refused. A repeated child event alone does not prove the callers were closed.

### Dated CR-04 acceptance correction — 2026-10-16

- **D-04:** Replace the unsupported source-backed `OpReturn` demand with the real checked-source path: `foreign.failed` at an indexed `OpForeignCall`, followed by its generated error block's `OpFail`, including a child failure routed through the caller's error edge to its own terminal. The original criterion was: “The peer independently derives propagated `OpReturn` failure source, type and outcome, preserving handled child failures and the existing `OpFail` path (CR-04). Real interpreter traces pass; wrong-source/type/outcome controls fail without accepting an event from its spelling alone.” Preserve that demand here and the original audit/probe unchanged as history.
- **D-05:** The correction is source-grounded: `checkForeignTracer` and resource-lifecycle lowering put `OpReturn` on success and `OpFail` on generated error blocks. Fresh model-only executions of checked/corevalidated `examples/phase24/error.schway` produced `foreign.failed → OpFail` for both UseError and AcquireError; an error-block `OpReturn` rewrite failed core validation with `core.owner_transfer_cleanup`. The audit's hand-built return probe lacks the required core facts and does not establish admitted reachability. This is a bounded observation, not proof that every possible raw core cannot reach `OpReturn && modeledFailure`. Leave that interpreter compatibility branch unclaimed; do not widen source syntax or allow `function.failed` at arbitrary `OpReturn` to satisfy the old probe.
- **D-06:** Admit `foreign.failed` only when its exact indexed operation and checked foreign contract support failure. Independently derive source place and declared failure type; resolve core type-fact IDs to the constructor representation actually used by events. Preserve ordinary `foreign.called`, `OpFail` attribution and root outcome-kind checks. Follow checked call/error-edge/target facts for activation-local failure provenance where the existing trace represents it; do not trust the kind/suffix, a bare matching error type, or a stale failure from another activation. A child failure must not by itself force the root outcome.
- **D-07:** Pin the causal boundary: this peer has no scalar inputs, foreign failure payload or branch-choice trace. It checks represented causal membership, identity, source/type attribution, admissible error links and terminal outcome kind; it does not replay numeric results, prove the branch actually taken, or authenticate `Outcome.Value` against an absent failure payload. Test literal expected typed-failure values independently in the interpreter/model oracle. Wrong source/type/root outcome-kind and a relabeled clean-return trace are meaningful peer controls. Do not add failure payload fields, branch events, a CFG evaluator or universal payload/path claims here.

### Native explicit defects and exact reason bytes

- **D-08:** Dispatch scalar `OpDefect` on the actual shell: application retains its failure path; native conformance uses the existing structured defect terminal even with zero `OpCall`. Do not use absence of dynamic invocation as an application-shell test. Reuse `emitProgramDefectTerminal` and existing native runner semantics: a complete defect document is transported with process exit 0 and then validated as a defect. This is distinct from application exit 65.
- **D-09:** Make a permanent, checker-admitted no-call scalar witness; assert the checked program has no `OpCall`. Run native O0, O3 and O3-LTO, require literal expected defect outcome/reason and independent peer acceptance, and retain the existing dynamic CR-05 entry/nested-helper control. Keep native Unit conformance refused; existing Unit application emission is not new native Unit admission. Application checks pin empty stdout, exit 65 and `schway app: ` + exact reason bytes + newline on the reached no-prior-output witness.
- **D-10:** Exact reasons include bytes already admitted by source, not only printable ASCII. Fresh narrow native application probes reached three mismatches: U+0001 followed by A became byte 0x1A; NUL followed by A became LF; NUL followed by Z truncated stderr before the reason/newline. The parser keeps raw reason bytes and does not decode textual backslash escapes. Repair only this field with C-safe counted emission: compile-time standard-library JSON escaping plus byte-counted structured output, and C-safe literal/byte-counted application stderr, or an equally small independently checked mechanism. Fixed-width C octal escapes alone do not fix NUL truncation. Preserve existing ordinary-reason tuples and parser semantics; do not add a source refusal or a generic string subsystem. The old corrupt control/NUL stderr is intentionally corrected to the existing exact-reason intent, with this dated compatibility decision.
- **D-11:** Preserve owner-scoped abort-like defect policy, capture/output limits, checked reason attribution, and ordinary resource/error cleanup rules. Closing peer frames is not physical cleanup proof. Do not create a claim that abort-like defects run arbitrary destructors, recover foreign faults or unwind across C ABI boundaries.
