## Critical Issues

### CR-01: Canonical clean/default controls run the defect suite for other proof subjects

**Classification:** BLOCKER  
**File:** `.planning/phases/37.1-close-gap-legacy-terminal-outcomes/371-prohibition-check.test.cjs:1044-1047`  
**Issue:** `runCanonicalProducer` inherits the environment without passing the active proof subject as `GSD_PROHIB_MODE`. For the bad fixture, `selectSubject()` identifies `failure`, `reason`, or `baseline`, and `runExactRoots()` selects that subject's suite even though the mode defaults to `defect` (lines 218-233 and 721-725). The clean fixture maps to subject `none`; with no requested mode propagated, it runs the default defect suite. The canonical producer can therefore report a proven fail-first result for a subject-specific bad run while its required clean causation control exercises a different suite. The manual controls avoid this mismatch by setting/passing the selected sample (lines 971-980 and 1003-1011), so they do not establish that the canonical producer's clean control is comparable.

**Fix:** Pass the active subject into `runCanonicalProducer` and set `GSD_PROHIB_MODE` in its child environment for both proof and default execution. Keep the canonical bad, clean, and default samples on the same exact suite, and validate that suite selection in the producer receipt or adapter output.

### CR-02: Parser and core-validation inputs are absent from proof freshness bindings

**Classification:** BLOCKER  
**File:** `.planning/phases/37.1-close-gap-legacy-terminal-outcomes/371-prohibition-check.test.cjs:1075-1085`  
**Issue:** `sourceBindings()` omits `internal/compiler/syntax/parser.go` and `internal/compiler/corevalidate/corevalidate.go`, although the reason proof overlays both files and claims to verify their current behavior (lines 291-295). The overlay records their current hashes as `originalSourceSha256`, but `assertArchivedProof()` validates only `source_bindings` and archived file records with `path`/`sha256`/`bytes` (lines 1116-1126 and 1140-1143); it does not revalidate those overlay hashes. Consequently, changes to either admission boundary do not invalidate archived proof bindings. They also produce no `changedPaths` entry in `beginSourceEvolution()`, so the source-evolution/archive gate can be skipped when these proof inputs change (lines 1214-1239).

**Fix:** Include both files in proof source bindings and validate the reason overlay's per-source hashes during archive checks. Route changes to those inputs through the existing source-evolution flow so prior proofs are preserved and fresh evidence is required.
