<language_surface_constraint>
No arithmetic, no iteration, no collections, no strings, no numeric type beyond
`Byte`; `match` is the only control flow. Fixtures use only `module`,
`export { fn ... }`, `data`, `fn f(p: T) -> T`,
`let x = borrow y | borrow mut y | take y | g(x)`, and `match`. Calls are
A-normal form (D-07-01): arity exactly 1, and the argument is the name of an
in-scope binding, never a nested expression. Only `Byte` and `Buffer` are
executable shapes (`check.executableShape`); every function's declared return
type equals its declared parameter type (`sameType` is enforced at the head of
`checkLinear`, `checkBranch`'s match path, and `checkFallibleLinear`), and each
function therefore carries exactly ONE type fact, `<functionID>:type:0`.

Two consequences the executor must not re-derive under pressure:
1. A **cross-function** type mismatch is expressible today (`f(v: Byte) -> Byte`
   called from `g(b: Buffer) -> Buffer`), which is what makes
   `call_type_mismatch.lang` a real fixture rather than a synthetic one.
2. A callee whose declared RETURN type differs from its declared PARAMETER type
   is NOT expressible today. So the return-derivation refusal is unreachable
   from source and must be mutation-killed through a seeded seam and through
   `corevalidate`'s synthetic input space — never by a `.lang` fixture. That is
   a fact to record, not a reason to skip the refusal.

<assumption_delta_decision>
`gsd_run query assumption-delta scan "07" --json` returned `detected: true`
(signals: `pluralization`). The signals themselves are weak, but the honest
delta in this plan is a `derived -> chosen` anchor move and it is recorded here
rather than dismissed.

- **Noun that is now primary:** the **callee's declared return contract** is the
  authority for a call result's type. Previously the caller's own argument place
  was the authority, and the callee's contract was not consulted at all.
- **Decision: `promote`.** The callee's declared return type is promoted to the
  primary source of `OpCall`'s `TargetID.TypeID`; the caller's argument type is
  demoted from "the answer" to "a fact that must now be PROVEN equal to the
  callee's declared parameter type before the call is admitted at all". This is
  a promote rather than an add-alongside: the old derivation is not retained as
  a parallel path, it is replaced.
- **Consequence recorded:** because every function today satisfies
  `ReturnType == Parameter.Type` and carries one type fact, the promoted
  derivation yields a byte-identical `TypeID` for every currently-admitted
  program. The promote is therefore observable only in the refusing direction
  today — which is precisely why Task 1 must PROVE the byte-identity rather than
  assume it, and why the return-derivation control needs a seeded seam.
- **What would force further change:** the moment a function may declare a
  return type differing from its parameter type, the caller will need a type
  fact it does not currently mint, and `check` will need to synthesize one. That
  is out of scope here and is recorded in PHASE-07-DEBT.md.
</assumption_delta_decision>

<task type="checkpoint:decision">
  <name>Checkpoint: ratify the four new diagnostic code strings and their cause shapes</name>
  <decision>
This plan mints FOUR agent-facing diagnostic code strings. They are published
API consumed by `lang-repair` and `lang explain`, so they are named once and
then frozen — exactly the discipline 07-05's own checkpoint applied to
`core.callee_not_callable`.

**`check`-side (emitted at admission time, span-bearing, from `resolveCallBinding`)**

1. `check.call_argument_type_mismatch` — the call's argument's type does not
   match the callee's declared parameter type.
   - `Primary`: `binding.RHS.Span` (the call site)
   - `Causes`, in this order:
     `{kind: "callee", detail: "<callee function ID>"}`,
     `{kind: "argument_type", detail: "<caller-side type constructor>"}`,
     `{kind: "declared_parameter_type", detail: "<callee's declared parameter type constructor>"}`
   - Constructor: `diagnostic.Error`, **no repairs.** No mechanical repair
     exists: fixing it requires either changing the argument or changing the
     callee's signature, and neither is a span-local replacement this checker
     can name. Offering a repair that does not repair is worse than none
     (D-07-31c's standing reasoning).

2. `check.call_return_type_unrepresentable` — the callee's declared return type
   names no type fact available in the calling function, so no honest
   `TargetID.TypeID` can be derived. This is the fail-closed half of deriving
   the target type from the callee rather than from the caller.
   - `Primary`: `binding.RHS.Span`
   - `Causes`: `{kind: "callee", detail: "<callee function ID>"}`,
     `{kind: "declared_return_type", detail: "<callee's declared return type constructor>"}`,
     `{kind: "available_type", detail: "<the calling function's own type constructor>"}`
   - Constructor: `diagnostic.Error`, no repairs.
   - **Declared now, so it is not discovered later:** this code is currently
     UNREACHABLE from any legal source program, because `sameType` forces every
     function's return type to equal its parameter type. It exists because the
     alternative — emitting a `TargetID.TypeID` the callee never declared —
     is the exact defect this plan closes. It is mutation-killed through a
     seeded seam, not through a fixture, and that is recorded in Task 3 and in
     PHASE-07-DEBT.md.

**`corevalidate`-side (the independent peer, on synthetic and real core)**

3. `core.CallArgumentTypeMismatch` = `"core.call_argument_type_mismatch"`
