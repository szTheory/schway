<threat_model>
Security enforcement is active at **ASVS L1**, blocking threshold **high**. The
security-relevant defect class in this codebase is **admission soundness**: an
unsound admission is this project's equivalent of an authorization bypass,
because every downstream stage treats an admitted `core.Program` as already
proven. Web-application threat categories (authn, session, transport) have no
surface here and are not fabricated into rows.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| untrusted `.lang` source -> `check` admission | The first of two independently authorized refusals. |
| `check`-produced `core.Program` -> `corevalidate` replay | The second, independent derivation. Its value is exactly its independence — and, as CR-04 shows, exactly its REACHABILITY. |
| peer verdict -> `protocol.Result` -> CLI exit status | The boundary this plan builds. A verdict that cannot cross it does not exist to the user. |
| `protocol.Result` -> `cmd/lang/main.go` exit code | `tool.operation_failed`/exit 3 for a real source defect misclassifies a defect as a malfunction; an agent consuming the JSON protocol cannot repair what it is told is a tool bug. |

  <decision>
Consulting the peer on `lang check` changes what the shipped binary says about
two programs. Both changes are CORRECT — the peer was always right and simply
could not be heard — but both are user-visible and one of them touches a
fixture this phase's own rules forbid disturbing. They are ratified here,
before any code is written, rather than absorbed into a diff.

**1. The union rule.** `CheckCommandFile` reports, in this fixed order:
   (a) `check`'s own diagnostics; then
   (b) `corevalidate.Validate`'s `Problems[0].Code` as `StatusInvalid`; then
   (c) `originvalidate.ValidatePublished`'s `problems[0].Code`, run on the
       peer-NORMALIZED program (`validated.Program()`), exactly as
       `InterfaceExportCommandFile` already does.
   The session layer contributes no predicate of its own. It never reconciles
   the two layers, never lets one suppress the other, and never averages them.

**2. `testdata/phase07/relay_escort_witness.lang` flips at the CLI.**
   `lang check` on it goes from `status: pass`, exit 0 to `status: invalid`
   with the peer's `core.move_while_borrowed`. This fixture is the disclosed
   D-03-02 interprocedural divergence, deferred to Phase 08/09.

   **What flips and what does not, stated precisely so this is not read as
   disturbing the deferral:**
   - `check.Program` on that fixture is UNCHANGED — still zero diagnostics.
     `TestRelayEscortWitnessChecksCleanPendingInterproceduralLiveness`
     (`check_test.go:2338`) asserts exactly that, against `check.Program`, and
     stays green byte-for-byte.
   - `corevalidate`'s verdict on that fixture is UNCHANGED — it already refused.
   - The DIVERGENCE ITSELF is unchanged: the two layers still disagree, and
     that disagreement is still deferred to Phase 08/09.
   - What changes is only that the disagreement is now VISIBLE at the CLI
     instead of being resolved silently in the admitting direction.
   - PVG-04 / CR-02 — `computeLoanLastUses`'s missing `"call"` case, the
     check-side cause of the divergence — is NOT fixed here and remains
     Phase 08 scope. This plan makes its consequence observable; it does not
     move its assignment.

**3. Duplicate function declarations start being refused at the CLI.** The peer
   already returns `core.duplicate_function_id`; once consulted, `lang check`

**4. The two `interface` paths stop reporting a source defect as a tool
