<objective>
Build the receipt-binding primitives that the producer, the gate and the ingest rely on (EVD-15; D-08, D-08a, D-08c, D-09, D-09a, D-10a):
- the code digest, in sh and in Go, with armed controls;
- the living-claim and receipt validator, which passes now and enforces after ingest.

SC3 says the gate rejects a receipt whose *revision* differs from the checked-out source. Here, revision = codedigest (D-08): the sha256 of the code paths at HEAD, so a `.planning`-only commit (such as the ingest commit) keeps the receipt current, while any code change moves it. The public-route audit (D-10b, D-10d) is plan 32-06, split out to keep this plan inside the context budget.

Purpose: a receipt binds to code, not to a commit, so `.planning` and prose commits cannot invalidate it. A later code change reopens it through a documentation-truth gate, not a CI tripwire.

Output: `scripts/codedigest.sh` and `session_phase32_receipt_test.go`.
</objective>
