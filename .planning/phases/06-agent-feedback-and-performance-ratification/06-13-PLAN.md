<objective>
Build `cmd/lang-repair`: a standalone, subprocess-only repair driver, and the deterministic
single-pass CI gate that scores it against the five held-out defect classes.

Purpose: DX-04's SC3 — an automated repair exercise fixes representative match, move,
borrow, cleanup, and stale-evidence defects using only the supported command protocol. The
gate proves the PROTOCOL is mechanically sufficient. The separately recorded, non-gating
agent exercise (06-15) is what proves the diagnostics are legible to a consumer who did not
author them; the two answer different questions and neither substitutes for the other
(D-06-23).
Output: the driver, the import boundary enforced structurally, and a non-degenerate success
oracle.
</objective>

  <action>
    Create `cmd/lang-repair/` as a standalone binary. It is architecturally its own tier,
    siloed from the compiler internals by a CI import-boundary lint — not by convention.

    `main.go` provides the CLI surface following `cmd/lang/main.go`'s style: flat arg
    matching, no `flag` package, no third-party library. Shape:
    `lang-repair --lang=PATH_TO_LANG_BINARY --source=FILE [--json]`.

    `repair.go` holds the driver logic:
    - Spawn the `lang` binary with `--json check FILE` via `os/exec`, capturing stdout with
      a bounded reader at a declared byte cap and a deadline, mirroring the bounded
      subprocess discipline used elsewhere in the tree.
    - Strict-decode the stdout JSON into locally declared structs. The driver may NOT import
      `internal/compiler/protocol` or `internal/compiler/diagnostic`; it re-declares the
      minimal fields it needs — `diagnostics[].code`, `diagnostics[].repairs[].kind`,
      `.span`, `.replacement`, `.applicability`. Re-declaration is the point: the driver is
      a protocol consumer, not a library consumer.
    - Select repairs where `applicability` is `MachineApplicable` AND both a span and a
      replacement are present. Everything else is reported as routed-to-exercise, never
      applied.
    - Apply the edit by splicing `replacement` into the source at exactly `[span.start,
      span.end)`. The driver reads the source file ONLY to perform this splice, and writes
      only within that range.
    - Never read `message` or `detail`. Do not even bind them into the local structs — a
      field that is not decoded cannot be scraped.

    The tracer: one `heldout_move_*.lang` fixture, injected by 06-12's move injector, handed
    to the driver, repaired, and re-verified by a second `lang --json check` subprocess
    reporting clean. One class, one path, real binary, real subprocess, real JSON.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `lang` subprocess stdout -> driver | The driver's ONLY permitted input; must be bounded and strictly decoded |
| `replacement` string -> source file splice | The tampering seam: an edit must not escape the span it was handed |
| `cmd/lang-repair` package -> `internal/` | The structural boundary D-06-28 enforces by build failure |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-BOUNDARY-01 | Elevation of Privilege | the driver importing compiler internals and ceasing to be a protocol consumer | high | mitigate | Broad `internal/` import-boundary test over every non-test file, proven non-inert by a fixture-directory positive control |
| T-06-BOUNDARY-02 | Tampering | a `replacement` splice escaping its declared span | high | mitigate | Out-of-range spans are refused, never clamped; write sites asserted by `go/ast` to target only the command-line source path |
| T-06-BOUNDARY-03 | Spoofing | the driver scraping prose and appearing to work from structure | high | mitigate | `message` and `detail` are not decoded at all — a field that is not bound cannot be read; asserted by `go/ast`; and 06-14's prose-scramble and vocabulary-removal guards falsify it independently |
| T-06-BOUNDARY-04 | Spoofing | the degenerate delete-the-code repair passing the oracle | high | mitigate | Byte-identity with the pre-defect original required alongside a clean check; `TestRepairOracleRejectsDeleteTheCode` is the positive control |
| T-06-BOUNDARY-05 | Denial of Service | unbounded subprocess stdout or a hanging `lang` invocation | medium | mitigate | Bounded reader at a declared cap plus a subprocess deadline |
| T-06-BOUNDARY-06 | Tampering | the driver spawning a program other than the `lang` binary it was given | medium | mitigate | `TestRepairDriverSpawnsOnlyTheLangBinary` asserts every exec site uses the `--lang` path variable |
</threat_model>
