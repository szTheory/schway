<hard_constraints_discovered_during_planning>
**Read these before designing the fixture. They are measured facts about the
shipped tree, not guesses, and two of them contradict the naive fixture shape.**

1. **A function's return type MUST equal its parameter type.** `check.go:170`,
   `check.go:2554`, and `check.go:2805` all guard `sameType(function.ReturnType,
   function.Parameter.Type)` and emit `type.return_mismatch` otherwise. A
   function therefore CANNOT accept an `Outcome` and return the extracted
   `Buffer`. The tracer function is `Outcome -> Outcome`.

2. **A match cannot mix arm forms.** `check.go:1637` emits
   `core.mixed_arm_forms` if any arm carries a body while another does not. The
   tracer fixture uses ONE arm form for all arms.

3. **Binding a payload MOVES it out of the scrutinee** (D-12-14), so the
   scrutinee is partially moved and cannot be handed back whole. The bound
   payload must be either re-constructed into a fresh alternative or dropped by
   function end. The tracer re-constructs — which is exactly what makes it
   exercise BOTH new operation kinds on one path.

4. **There is no arithmetic, no `if`, no iteration, no strings, no arrays.**
   Payload types available are `Byte`, `Buffer`, and nullary ADTs
   (`.planning/LANGUAGE-MATURITY.md`). Do not author a fixture that assumes
   otherwise.

**The tracer fixture shape these constraints force** (bare-alternative arm-value
form, matching `testdata/phase1/toggle.lang`'s `Off => On` shape extended with
constructor application):

```
module result.payload_tracer

export {
  type Fault
  type Outcome
  fn identity
}

data Fault =
  | Broken

data Outcome =
  | Ok(Buffer)
  | Err(Fault)

fn identity(result: Outcome) -> Outcome {
  match result {
    Ok(v) => Ok(v)
    Err(e) => Err(e)
  }
}
```

If this exact spelling does not check, adjust the fixture — never the
constraints — and record the adjustment and its reason in the SUMMARY per
D-09-45.
