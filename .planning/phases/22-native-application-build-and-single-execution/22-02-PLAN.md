## Planning decisions (delegated, not user-locked)

- `lang build SOURCE --manifest MANIFEST --output ARTIFACT` extends the pure-source command from 22-01. The optional manifest is required when local C is compiled. `lang.local-c/1` is closed JSON with `sources`, `headers`, `include_dirs`, `symbols` entries `{name, header, function_type}`, and `runtime_dependencies`. A named C header defines a function typedef; `function_type` names that typedef. A generated C17 probe includes the declared header and assigns the symbol address to a pointer of that typedef, requiring compiler type agreement and a linked symbol reference. This choice accommodates Phase 23 resource pointer types through a C typedef without pre-admitting any foreign call.
- All paths are relative to the manifest directory. Reject absolute paths, parent traversal, symlink escape, missing files, duplicate declarations, duplicate JSON keys and undeclared C include paths; use Clang dependency output to require and hash every actual local included header, and normalize slash names for identity so checkout relocation does not alter it. Explicitly limit runtime dependencies in this phase to the host platform C runtime and record it in the receipt. Unknown host linker/SDK dependency closure is `incomplete` and forbids cache reuse or a complete-provenance claim, even though known content digests remain stable.
- Build identity hashes length-delimited canonical fields: Lang source bytes, emitted C bytes, canonical manifest content and normalized names, every declared source/header byte digest, symbol/typedef declarations, compiler executable digest/version, target triple/host ABI, fixed compile/link argv, runtime declarations, and final artifact bytes. Output path is recorded outside the content hash. No absolute checkout path becomes an identity field. Every evidence sidecar later references this build ID and verifies the artifact digest.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Manifest → filesystem and Clang | Explicit trusted build authority still requires path confinement and argv-only compiler calls. |
| Declared ABI → linked local C | Header/typedef checks establish declaration compatibility; arbitrary C implementation behavior remains trusted. |
| Build inputs → artifact/evidence ID | A stale or incomplete dependency inventory can falsely identify different binaries as the same build. |
