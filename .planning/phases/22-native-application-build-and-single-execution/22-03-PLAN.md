## Planning decisions (delegated, not user-locked)

- Ordinary syntax is `lang app run ARTIFACT [--report REPORT] [--evidence=events] -- INPUT`. `--report` alone writes a `lang.app-evidence/1` sidecar with capture status `disabled`; adding `--evidence=events` captures checked compiler events from the same child in a private temporary file and then publishes the report. The report contains build ID/artifact digest, input digest, process outcome, capture status (`disabled`, `complete`, `incomplete`, `capacity_exhausted`), optional bounded execution document, and `verified:false`. `complete` means the capture was structurally complete, not independently checked. An absent, truncated, malformed or over-budget capture cannot set `complete`; incomplete or exhausted requested capture returns a tool failure while preserving app streams and recording the child outcome. Report writes are atomic; a failed write is a tool error. No report is emitted when no report was requested.
- `lang app verify SOURCE --cases CASES --report REPORT` is an explicit conformance route. `lang.replay-cases/1` records isolated input tokens and independently authored expected terminal value/output for identity cases 7 and 42; those ordinary source cases declare empty `foreign_outcomes` scripts and run through interpreter/O0/O3. Separately, the closed verifier-case schema includes `kind: verifier_model_only`, dispatched by the explicit verifier to its verifier-owned deterministic model adapter, without compiling a Lang foreign call. Its positive case (authored inline in `cmd/lang/main_test.go`) declares synthetic operation `fixture.value`, one scripted U64 outcome (42), and independent expected value (42); the adapter consumes that outcome exactly once and compares its result with the expected value. It does not invoke foreign lowering or execute local C and cannot make the identity application's source-level FFI-capable. Missing, duplicate, unconsumed, and mismatched scripted outcomes fail closed. Its report labels the case `verifier_model_only` and sets actual-host-IO and physical-cleanup claims false. The verifier writes `verified:true` only when each applicable case's comparisons and declared evidence pass. Unknown host toolchain closure remains explicitly incomplete and prevents cache reuse or a complete-provenance claim; it does not erase a correctly scoped execution comparison. Phase 23 may extend the replay world with its contracted adapter.
- Evidence capture uses the generated app's existing event recorder and a process-private file selected by the parent; no event protocol bytes enter ordinary stdout/stderr. The app output remains byte-identical with evidence on or off. Event capacity and report size are fixed at 64 KiB for this phase, with a test-only smaller injected bound for the exhausted control.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Generated child → compiler evidence sidecar | Captured bytes may be missing, truncated or malformed and cannot authenticate themselves as verified. |
| Replay cases → interpreter/native executions | Expected answers and declared foreign outcomes are independently supplied, bounded, and confined to explicit verification. |
| Modeled outcome → external-world claim | A declared foreign result is a model fact, not evidence of actual host IO or physical destruction. |
