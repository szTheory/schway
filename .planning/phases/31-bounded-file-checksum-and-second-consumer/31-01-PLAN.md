Then add one `#ifndef SCHWAY_FILE_BYTES_<HOOK>` / `#define ... <real fn>` / `#endif` per hook: OPEN→open, FSTAT→fstat, READ→read, MALLOC→malloc, REALLOC→realloc, FREE→free, CLOSE→close.

`schway_file_bytes_acquire` runs these steps:
1. A NULL or empty path returns status 2.
2. `OPEN(path, O_RDONLY | O_NONBLOCK)` < 0 returns status 2.
3. If `FSTAT` fails or `!S_ISREG(st_mode)`, close and return 2.
4. `MALLOC(SCHWAY_FILE_BYTES_LIMIT + 1)` NULL: close and return 3.
5. Loop `READ` into the remaining capacity until 65,537 bytes are received or the read returns 0. A positive count accumulates. `-1` with `errno == EINTR` continues. Any other `-1` frees the buffer once, closes, and returns 2.
6. Received > 65,536: free once, close, and return 1 (FileTooLarge). Never consult the stat-reported size field; the read count is the only size.
7. Otherwise `REALLOC(buf, received ? received : 1)`. NULL: free the original once, close, and return 3. This gives ASan an exact-size block for plan 31-08.
8. `CLOSE` failure frees once and returns 2.
9. Success returns status 0 and the owner `{data, received}`.

The adapter writes NOTHING to stdout or stderr: it makes no stdio output call of any kind. `schway_file_bytes_view` returns `{owner.data, owner.length}`, and `schway_file_bytes_release` calls `FREE(owner.data)`.
