<objective>
Make build identity and evidence hash every module file in sorted order (MOD-06, D-11, D-19). Add a trailing `Modules []ModuleDigest` with `json:"modules,omitempty"` to the identity inputs, the receipt and the evidence report. It is populated from the single modload read, and only when the program has imports, so every no-import ID and receipt stays byte-identical.

Purpose: without this, a library edit would not change the BuildID of the applications that import the library, and the dual flip in plan 31-07 could not show both identities moving.

Output: the native fields, API variant and receipt validation; the session wiring in a new file; and the module-digest tests with their controls.
</objective>

<assumption_delta_decision>
Detector fired (pluralization: a second application now imports the same library, and identity now covers more than one source file).
- Primary noun: the loaded module set. `Modules` (every module, entry included, sorted by module name) is now the full identity of the source.
- Decision: `add-alongside`. `SourceDigest` stays the entry-only digest next to `Modules`.
- Rationale: D-11 and D-19 lock this. Promoting `Modules` to replace `SourceDigest` would change every no-import BuildID, receipt and golden, which is what the `ForeignDigest` omitempty precedent avoids.
- Accepted debt: the entry digest is recorded twice when imports exist. Receipt validation enforces that the two agree. A future change that makes every program carry `Modules` (for example, a receipt schema bump) would force the promote.
- Invariant test: `TestPhase31ModuleDigests` asserts the entry row equals `SourceDigest` and that the no-import marshal is byte-identical, so a later change that re-singularizes identity fails.
</assumption_delta_decision>
