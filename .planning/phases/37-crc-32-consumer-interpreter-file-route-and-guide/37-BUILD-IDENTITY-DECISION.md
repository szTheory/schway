# Build identity evidence amendment — 2026-10-15

During 37-06 the real no-edit CRC builds had stable module rows and input identity, but different executable digests and full build identities. This was a concrete counterexample to the plan's stronger no-edit identity assumption. The executor paused at its architectural deviation boundary; the parent selected this amendment under the user's delegated recommendation authority. No human approval is fabricated.

The existing source contract already separates the identities: `internal/compiler/native/bindings.go` defines InputID by excluding ExecutableDigest, while BuildID binds that digest. `internal/compiler/native/bindings_test.go`'s retained relocation test explicitly permits BuildID variance when executable bytes differ, provided InputID agrees and receipts remain non-cacheable with incomplete dependency closure. Source inspection, not a newly executed regression of that older test, established this contract.

Recommendation adopted: preserve the existing native build implementation. Require identical module rows and InputID on no-edit reruns, full receipt self-consistency, and equal BuildID whenever executable digests match. A library-only edit must change both importers' module digests, InputIDs, and real numerical outputs while preserving entry/adapter bytes. BuildID variance by itself is insufficient invalidation evidence. Record actual artifact digest/BuildID observations and retain the incomplete/non-cacheable posture.

Rejected for this phase: removing Mach-O UUIDs, normalizing executable bytes, changing linker selection or claiming reproducible native artifacts. Those widen the production build contract beyond the CRC consumer. Apple's primary [ld manual](https://github.com/apple-oss-distributions/ld64/blob/main/doc/man/man1/ld-classic.1) describes hash-derived UUIDs by default and warns that `-no_uuid` may impair debugger/crash tracking. The local differing UUID observation does not establish that Apple linkers generally default to random UUIDs. [Apple TN3178](https://developer.apple.com/documentation/technotes/tn3178-checking-for-and-resolving-build-uuid-problems) is the relevant UUID diagnostic reference; only its search excerpt was accessible during this review, so no additional technical claim relies on its unread body.

37-06-PLAN.md preserves its original wording and carries a dated clarification. Its final focused selector passed in executor evidence; parent wave checks and final independent verification remain separate. D-18's module-digest and dual-output obligations remain unchanged. No production linker flag, wire schema, identity hash algorithm or dependency was changed.
