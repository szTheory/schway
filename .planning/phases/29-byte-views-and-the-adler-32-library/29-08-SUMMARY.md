# Phase 29 Plan 08: Interpreter fixture runnable gain Summary

`interp.RunWithFixtureBytes` runs `examples/phase29/adler32_fixture.schway` in the interpreter with bytes from the caller-supplied generator (`testsupport.Phase29FixtureBytes`), returning every pinned checksum for case ids 0..9, and treats only the byte-index defect as abort-like with the owner live.

## Accomplishments

- Interpreter replays the fixture lifecycle: acquire binds an owner holding a copy of the generated bytes and registers it live; borrow yields a read-only view sharing the bytes (no owner identity); the call passes the view by the ordinary frame-copy rule; release discharges the owner. A normal return leaves no live resources.
- D-07: production interp contains no fixture table, no adapter reference, no file access (grep gate returns 0).
- Unknown case 10: acquire fails with `typed_failure FixtureMissing`, no owner published, no live resources, no release or leak events.
- D-19/D-20: out-of-range `byte_at` yields an empty defect with final event `function.defected` / "byte index out of bounds" and the owner live; accepted. A `defect "boom"` statement and a U64 overflow, each raised in the callee with the owner live, are still rejected with the live-resources error (armed controls).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Callee defects reported no live resources**
- **Found during:** Task 1 design / Task 2 controls
- **Issue:** The existing defect and terminal arms report only the terminating frame's live set. The fixture owner lives in `main`, so a defect in the `adler32` callee would report none, making the D-20 rule and its armed controls unobservable.
- **Fix:** Added `terminalLiveResources(stack, top)`, which reports the whole stack only when the frame carries the fixture generator and otherwise returns `frameLiveResourceList(top)` unchanged. `fixtureBytes` is propagated to callee frames at OpCall.
- **Files modified:** internal/compiler/interp/interp.go
- **Commit:** bb99382
