## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| byte view -> interpreter read | any index reaching the payload slice must pass the length comparison | U64 index, byte payload |
| byte view -> emitted C load | any index reaching `data[index]` must pass the bounds `if` | U64 index, foreign byte buffer |
| harness bytes -> interpreter / proxy | test bytes enter only through `RunByteViewForTest` or the proxy driver | test byte vectors |
| source text -> parser | untrusted program text reaches the new `byte_len` / `byte_at` atom branches | program source |
| typed core -> each validator | a forged or coordinated false core statement must be caught by an independent law | typed core IR |
| execution document -> executionpeer | engine evidence is untrusted until the peer classifies it | execution evidence |
| case id (U64 app argument) -> adapter | an untrusted integer, at most 4,096 bytes of text, selects a fixture case | U64 case id |
| adapter buffer -> generated code | the data pointer and length cross the C ABI | pointer, length (trusted foreign fact) |
| foreign C block policies -> checker | declared foreign contracts are trusted only after exact shape and policy gates | foreign contract facts |
| owner -> view loan -> callee | the view must not outlive the owner or escape `main` | ByteView loan |
| binding manifest -> native build | the manifest names the sources and headers compiled into the artifact | file paths, symbol set |
| caller generator -> interpreter owner | interpreter bytes come only from the generator parameter | generated bytes |
| optimizer -> emitted bounds check | -O3 and LTO must not remove the observable check | emitted C |
| test seams -> production build | seams must be inert in production | package-level test switches |
| planning documents -> meta-tests | enforced documents must stay grounded in real tests and counts | planning claims |
| local repository -> remote/CI; timing -> cap decision | push and dispatch are user-gated; wall time decides the cap | git refs, timing readings |

## Notes (non-register observations from 29-REVIEW.md)

The audit verified only the registered mitigations. Two code-review warnings touch this register's trust assumptions. 29-VERIFICATION.md classifies both as non-blocking, and both remain `open` in 29-REVIEW-DISPOSITION.md:

- **WR-01:** the fixture owner is called "test-only", but any user program and manifest can reach it. A user-supplied adapter `length` is a trusted foreign fact, the same trust class as every local-C owner. The "test-only" wording is not a security boundary. T-29-04 and T-29-28 guarantee the bounds check only against an honest adapter length.
- **WR-04:** about eight `disable...ForTest` vars and `applicationCSourceMutationForTest` sit in production packages. Their setters are test-only, so T-29-29 holds as planned. The vars are read without synchronization. Moving them behind a test-only build mechanism would harden this.
