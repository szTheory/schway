<objective>
Close verification gap 2 by proving the conformance translation unit is
independently scanned, and by pinning the production lane's scanned-artifact
count so a future refactor cannot silently shrink it.

Purpose: 04-VERIFICATION.md scored the 04-03 must_have about D-04-12's three
inspectable layers as FAILED because `control:foreign.no_unproven_attributes`
scanned only `cgen.Emit` and `cgen.EmitForeignManifest` output — two of the three
named layers were never passed to `cgen.ScanForBannedAttributes` anywhere in the
repository. Commit `cb701b5` (the WR-01 fix pass) wired
`cgen.EmitForeignHeader` and `cgen.EmitForeignConformance` into the lane for both
fixture programs, and added `TestAttributeInjectionIntoHeaderOnlyMakesControlFail`.

What remains open, and what this plan closes:
1. There is still NO falsifier for the conformance layer. `EmitForeignConformance`
   EMBEDS `EmitForeignHeader`'s full output, so the existing header-only test
   proves nothing about the conformance unit's OWN added text (the private-header
   `#include` line and the per-field `_Static_assert` triples). A banned token
   introduced into that region alone has no test that would catch it — the exact
   "coincidental byte-identical format string" trap 04-VERIFICATION.md's own
   `missing:` item 2 warns about, one layer further in.
2. Nothing asserts HOW MANY artifacts the production lane scans. Deleting an
   argument from the `ScanForBannedAttributes` call in `session.go` today turns
   no test red — the lane would still pass, still report the required control,
   and coverage would regress to exactly the state that failed verification.
3. Neither the WR-01 fix nor its successor has a Mutation-Kill Register row.

Output: two new tests in `session_test.go` and two register rows. No production
code changes — `session.go` and `cgen.go` are already correct; what is missing is
the falsifier that makes them stay correct.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `cgen` emitted C → the C compiler / optimizer | an optimizer-visible attribute crossing here is a claim the compiler will act on; an unproven one produces wrong code, not slow code (D-04-13) |
| generated header / conformance TU → human reviewer | D-04-12's inspectability claim: a reviewer reads these artifacts and trusts what they carry |
| `cgen` → `session` gate lane | the control identifier asserts full coverage; the argument list decides actual coverage |
