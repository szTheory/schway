<objective>
Close 04-VERIFICATION.md gap 2 (04-REVIEW.md's new CR-02): make `corevalidate`
actually AUDIT the shape of `core.ForeignContract.Symbol` before any emitter
splices it into generated C, and give `cgen` its own independent refusal on the
three exported entry points that never call `Validate` — so a corrupted
`core.Program` cannot inject arbitrary C source at the one boundary this phase's
goal calls "audited".

Purpose: corevalidate.go:300 checks only
`function.ForeignContract != nil && function.ForeignContract.Symbol != ""` —
presence, never shape. Confirmed by direct read: there is no identifier-shape
check anywhere in `corevalidate.go`. `cgen` then splices the value raw into
generated C at `foreignExternName` (cgen.go:778, `return "_LANG_" + symbol`),
into the `extern` declaration built from it (cgen.go:352 and its `Fprintf`),
into the call-expression callee (cgen.go:1278 and its call site), and into a C
comment in the generated foreign header (cgen.go:1289, `/* symbol: %s */`, where
a Symbol containing a comment terminator escapes the comment). Every OTHER
emitted identifier is routed through `cName` (cgen.go:1456) or `cLocal`
(cgen.go:1474), both of which replace every character outside `[A-Za-z0-9_]`.
`Symbol` is the single exception, and `cgen.Emit`/`EmitNative`/`EmitForeign*`
are exported and accept any caller-supplied `core.Program`. A Symbol carrying a
semicolon, a parenthesis, a brace, or a newline therefore passes validation
today and is spliced verbatim into a translation unit this compiler then
compiles and, via `session.RunNative`, executes. That is a direct violation of
FFI-01/D-04-12's "no layer can invent a fact the contract does not carry": an
unaudited identifier field is exactly a fact `cgen` trusts without the audit
gate having checked it.

What this plan does NOT do: it does not change `foreignExternName`'s deliberate
bypass of the `cName` allocator (documented at cgen.go:771-777 — the extern name
must match a real exported symbol in the byte-frozen foreign translation unit
verbatim, so sanitizing it would break linkage). Instead it makes the INPUT
provably identifier-shaped, which is the only fix compatible with that
constraint. It does not touch `check.go` (whose parser already produces
identifier-shaped symbols on the honest path), does not touch any golden, and
does not add a Symbol length bound.

Output: the audit and its helper in `corevalidate.go`, cgen's independent peer
check in `cgen.go`, one falsifier in `corevalidate_test.go`, two regression tests
in `cgen_test.go`, one Mutation-Kill Register row.
</objective>
