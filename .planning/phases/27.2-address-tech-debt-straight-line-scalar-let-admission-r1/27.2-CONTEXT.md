# Phase 27.2: Address tech debt: straight-line scalar let admission (R1) - Context

**Gathered:** 2026-10-10
**Status:** Ready for planning

<domain>
## Phase Boundary

Restore admission of **branch-free scalar function bodies** end to end
(`check` → corevalidate → origin peer → `build` → `app run`), fixing the
milestone re-audit finding R1 at its root cause, producer-side, with every
independent validator unchanged.

R1 as audited: `fn main(n: U64) -> U64 { let total = n  total }` is refused by
`schway check`/`schway build` with `core.release_order_indeterminate`; the parent
of a671308 (`feat(26-05): lower source-authored scalar lets as copies`) accepted
and ran it (`app run -- 41` prints 41).

Discuss-phase root-cause findings (reproduced 2026-10-10 at 2be2430, CLI built
into the scratchpad):

1. **CFG shape defect (pre-existing since Phase 26).** Every scalar linear body
   with no `if`/`while` leaves its `OpReturn` in the entry block. corevalidate's
   terminal-block rule (`corevalidate.go` ~4237: a block ending in
   `OpReturn`/`OpFail` must have ≥1 incoming edge) refuses it. This affects
   `var` bodies too: `var total = n  total` and `var t = n  t = t + 1  t` were
   **already refused at a671308~1** (fb1f61e). a671308 only routed `let`-led
   bodies into the scalar builder (`parser.go` `atAny(TokenLet, …)`), turning a
   previously-working `let` program into a victim. It is also the "branchless
   Unit witness" refusal noted (not escalated) in `27-05-SUMMARY.md` line 140.
2. **Emitter classification defect (masked by 1).** A local prototype that split
   entry →`next`→ return-block in `check/scalar.go` made all shapes pass
   `check`, and `var`/`let … + 1` bodies then built and printed 42. But bodies
   whose ops are only copy/const/write/return (`let total = n  total`;
   `let x = n  write_u64(x)  write_newline()`) fail `schway build` with
   `native.build_failed: … multi-function foreign-call bodies are not supported`,
   because `cgen.hasScalarOperations` (`cgen_program.go:2504`) recognises a
   scalar body only by `AddChecked/LessU64/EqualU64/RemainderU64/ScalarStore/Branch`.
   The peers' classifiers (`corevalidate.hasScalarCFG` ~4298,
   `originvalidate.originHasScalarCFG` ~293) additionally include the three write
   ops; **none** counts `OpCopy`/`OpConst`. The three sets disagree today.

In scope: the branch-free shapes `let`-only, `var`-only, `var` + assignment,
mixed `let`/`var` with arithmetic, pure copy (`let total = n  total`), pure
constant, and Unit write-only bodies — U64→U64 and U64→Unit entries.

Out of scope: any new syntax or capability; any change to corevalidate,
originvalidate, executionpeer or interp acceptance rules; W1–W4 and the
D-27.1-10 deferrals.
</domain>

<decisions>
## Implementation Decisions

### Fix site and scope (user-selected: "Root cause, producer-side")
- **D-27.2-01:** Fix the root cause for **all** branch-free scalar bodies (let,
  var, mixed, pure copy, pure const, Unit write-only), not only the audited
  `let` case. Both defects (CFG shape and emitter classification) are in scope
  because fixing only the first leaves pure-copy `let`, the audited R1 program
  itself, unbuildable.
- **D-27.2-02:** Producer-side only. The checker's scalar builder
  (`internal/compiler/check/scalar.go`) must emit a core shape that the
  **unchanged** corevalidate and originvalidate already accept. Do **not** relax
  the terminal-block rule or any other independent-peer rule, and do not widen
  peer classifiers to fit the producer. Rationale: peers are the trust
  boundary; fitting them to producer output inverts that. —
  **Reversibility:** reversible — producer-local.
- **D-27.2-03:** Candidate mechanisms for the CFG fix. The researcher picks one
  with evidence; the planner locks it:
  - (a) **Return-block split** (prototype-validated for `check`): when lowering
    ends with the current block still the entry block and not terminated, add
    a `return` block and an unconditional `next` edge entry→return, then place
    `OpReturn` there. This reuses the `next` edge shape `while` already emits
    (preheader→condition) and `if` emits (arm→join), so every peer, interp and
    cgen already handle it.
  - (b) **Blockless form:** emit the straight-line body with no blocks or edges,
    the M001–M004 linear shape that the pre-a671308 `let` path produced and that
    corevalidate's terminal-block loop never visits. Researcher must verify
    that scalar ops (`ScalarStore`, `AddChecked`, writes) are accepted blockless
    by corevalidate, originvalidate, interp, executionpeer and cgen before this
    can be chosen.
  Default to (a) unless research shows a concrete defect in it.
- **D-27.2-04:** Emitter classification (cgen is producer-side, not a peer).
  `cgen` must emit every body that the checker, corevalidate and originvalidate
  jointly accept as a scalar CFG body, including copy/const/write-only bodies.
  The fix must not let an ownership-kernel body (Owner/Resource/Loan places,
  `OpMove`, borrows, foreign calls, releases) reach the scalar emitter. The
  existing refusal tests for "multi-function foreign-call bodies" and
  "by-pointer bodies" (`cgen_test.go`, `native/*_test.go`, `core/core_test.go`)
  must keep passing unchanged. The planner chooses the exact rule, e.g. aligning
  cgen with the peers' op set plus a "every place is U64/Bool/Unit and every op
  is in the scalar set" structural test. If the emitter fix needs an interp or
  executionpeer change to keep engines agreeing, that is in scope only as
  producer/engine parity, never as a validator relaxation.
- **D-27.2-05:** Already-accepted programs must be **byte-identical**: the same
  core documents/hashes and the same emitted C for `examples/sum_to_n.schway`,
  `examples/fizzbuzz.schway`, `examples/checksum.schway`, and the
  `examples/phase22…27` and `testdata/` positive controls. The CFG fix may only
  change programs whose return currently lands in the entry block (all of
  which are currently refused). Pin this with a test, not by assertion. Pinned
  example source and fixture hashes (27 / 27.1 receipts) must not change.

### Evidence bar
- **D-27.2-06:** Red→green, as in D-27.1-14: focused tests fail before the fix
  (refusal codes above) and pass after. Witness set: the shapes listed under
  In scope. Each must pass `check`, `build`, then `app run`, with the expected
  stdout (e.g. `41` for pure copy, `42` for `+ 1`, `hi\n` for write-only), and
  agree across the interpreter application API and the native route. The R1
  program from the audit is the headline control and should be a committed
  fixture (e.g. under `examples/phase27_2/` or `testdata/`; planner chooses,
  following existing naming).
- **D-27.2-07:** Negative controls (codes corrected by research, 27.2-RESEARCH.md):
  checker refusals stay unchanged before and after (`name.uninitialized_place`,
  `name.unknown_place`, `type.scalar_result`, `type.unit_result`,
  `type.scalar_remainder_zero` for a constant zero divisor). The unreachable
  trailing result after an `if` whose arms both terminate stays refused with
  `core.terminal_block_unreachable`; its diagnostic quality is deferred. A
  straight-line overflowing `+` is a runtime defect, not a static refusal. It
  is refused at HEAD only as a side effect of R1. After the fix it must check
  and build, then fail at runtime: interpreter `OutcomeDefect` "U64 addition
  overflow"; native exit 65, empty stdout, stderr
  `schway: U64 addition overflow\n`. This control is red→green, not
  unchanged.
- **D-27.2-08:** Local runs: focused `go test -run` only, plus the session
  meta-tests (`Inventory|Groundedness|Reconciliation|ValidationLifecycle`)
  before any commit of planning docs. Full and race suites run hosted only:
  one `ci.yml` `workflow_dispatch` (default inputs) at the final 27.2 SHA on
  both hosts, behind an explicit user approval checkpoint for push and
  dispatch, with no force-push and no pushes during the run. Record run
  ID/URL/SHA and per-job conclusions in the 27.2 verification. Fresh Phase 27
  receipts are **not** required, because example sources, fixtures and emitted
  bytes are unchanged (D-27.2-05). If the hosted receipt lanes run anyway,
  cite them; do not commit new receipt files unless the gate is re-run pinned
  to that SHA.
- **D-27.2-09:** Record-keeping: add a dated addendum to `26-VERIFICATION.md`
  (FLOW-01/U64-01: straight-line scalar bodies restored; R1 root cause predates
  a671308 for `var`). Update the milestone audit's R1 row on the next
  `/gsd-audit-milestone`, not inside this phase. The phase maps no new
  requirement IDs; it restores assurance for FLOW-01 and U64-01.

### Added after research (orchestrator, advisor mode, minimal_decisive)
- **D-27.2-10:** Option (a), the return-block split, is locked for D-27.2-03.
  Option (b), the blockless form, is rejected: cgen's scalar emitter emits
  `goto schway_block_-1`.
- **D-27.2-11:** Third producer-side defect in scope: cgen
  `emitProgramScalarFunction` must mark the entry parameter used, e.g.
  `(void)param;`, **only** when no operation reads it, so that the emitted C
  of every currently accepted program stays byte-identical (D-27.2-05). This
  covers pure const, write-only and constant-only overflow bodies, which
  otherwise fail clang `-Werror,-Wunused-parameter`.
- **D-27.2-12:** Second a671308 regression R1b (`let a = n  let b = helper(a)  b`
  → `syntax.expected_linear_result`, parser routing on the first `let` only)
  is **deferred**. It is parser routing logic outside the scalar-builder
  scope. Add a characterization test pinning current HEAD behavior, and record
  it as R1b in the `26-VERIFICATION.md` addendum (prose, not a DEBT register).
- **D-27.2-13:** A Unit `let`-only body that prints nothing is an acceptable
  witness (empty stdout, exit 0, engines agree).
- **D-27.2-14:** New fixtures go under `examples/phase272/`, not
  `testdata/phase*/`, because corpus tests glob that path. The byte-identity
  guard (D-27.2-05) is a session test over the accepted corpus against a
  golden hash file generated at the pre-fix HEAD. New tests use
  `cgen.EmitApplication` only (never `cgen.Emit`/`cgen.EmitNative`, which the
  Phase 16 inventory tracks).

<specifics>
## Specific Ideas

- Headline witness, verbatim from the audit:
  `module t.sl` / `export { fn main }` / `fn main(n: U64) -> U64 { let total = n  total }`,
  where `app run -- 41` prints `41`.
- Prototype (discarded, not committed) for D-27.2-03(a), placed after
  `b.lower(...)` in `checkScalarFunction`:
  `if len(b.diagnostics)==0 && b.current==0 && !b.terminated(0) { e := b.blocks[0].ID; r := b.newBlock("return"); b.edge(e, r, "next") }`.
  This passed `check` for all in-scope shapes and built/ran var and arithmetic
  shapes (stdout 42). Pure-copy and Unit write-only then hit the cgen
  classifier (D-27.2-04).
- `schway run --engine=…` returns operational_failure for scalar entries even on
  `examples/sum_to_n.schway` at HEAD (W3 territory). Do not use `run` as the
  witness route; use `build` + `app run` and the interpreter application API.

</specifics>
