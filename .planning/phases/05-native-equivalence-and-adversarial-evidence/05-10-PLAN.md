<objective>
Build the core-level reducer: five fixed moves applied in deterministic order to
fixpoint, a strict interestingness predicate, and a bounded work budget whose
exhaustion is recorded rather than hidden.

Purpose: INT-02 requires that an interpreter mismatch report the smallest KNOWN
source/core case with causal facts. This project's identity discipline is
function-local ordinals, never source offsets, which is exactly why text- and
offset-based reducers are the wrong tool: they collide head-on with that
discipline and can emit structurally invalid candidates. A five-move HDD over the
typed core is the right size for a grammar with one parameter and no loops.

Output: `internal/compiler/reduce/` with `Reduce`, the five moves, the predicate,
and the work accounting. Plan 05-12 adds the `lang.mismatch/0` document and the
three required mutation-kills.
</objective>

  <action>
    Create the new package `internal/compiler/reduce`.

    Declare `type Move struct { Name string; Apply func(core.Program) (core.Program, bool) }`
    and `func Moves() []Move` returning EXACTLY these five, in this exact order —
    the order is the determinism guarantee and must not be sorted, shuffled, or
    made configurable:

    1. `drop-unused-binding` — remove a binding no later operation reads.
    2. `drop-unmatched-arm` — remove an unreachable or non-matching `match` arm.
    3. `drop-offpath-foreign-stage` — remove a foreign acquisition/release stage
       that is not on the diverging causal path.
    4. `collapse-branch-to-diverging-arm` — collapse a two-arm branch to the arm
       containing the divergence.
    5. `truncate-to-minimal-prefix` — truncate a straight-line body to its
       terminator plus the minimal prefix reaching the diverging operation.

    Each `Apply` returns the reduced program and `false` when the move does not
    apply. Moves operate on `core.Program` structure only — the operation list and
    block graph. No function in this package may accept, return, or parse source
    text.

    Declare `const MaxReductionAttempts = 64`.

    Declare `func Reduce(ctx context.Context, seed core.Program, interesting Predicate)
    (Result, error)` applying the moves greedily in fixed order to fixpoint: try
    move 1 repeatedly until it stops applying or its candidate is uninteresting,
    then move 2, and so on; on reaching move 5, restart from move 1 if any move
    applied in that pass. Terminate on a full pass with no accepted candidate
    (fixpoint) or on `MaxReductionAttempts` check+compile+execute cycles.

    `type Result struct { Program core.Program; Minimality string; Attempts int;
    TotalRecomputedWork int; AppliedMoves []string }` where `Minimality` is exactly
    `"fixpoint"` or `"budget_exhausted"`.

    Per D-05-25: budget exhaustion sets `Minimality: "budget_exhausted"` and returns
    a NON-error result. It is not a lane failure — it is INT-02's "smallest known
    case" hedge made mechanical.

    Each attempt's work is summed into `TotalRecomputedWork` in the same currency
    every other lane uses; do not introduce a second cost unit.

    Do NOT build a general delta-debugging engine. Five moves, fixed order, no
    randomization, no seed. `bugpoint`'s documented failure mode was exactly a
    pass-oblivious generic reducer that was slow and confusing.

    Tests:
    - `TestReduceHasExactlyFiveMoves` — `len(Moves()) == 5` and the names match the
      five literals above in order.
    - `TestReduceIsDeterministic` — the same seed and predicate produce a
      byte-identical serialized reduced program across repeated runs and across
      separate processes.
    - `TestReduceRespectsBudget` — a seed engineered to never reach fixpoint within
      64 cycles yields `Minimality: "budget_exhausted"` with `Attempts == 64` and a
      nil error.
    - `TestReduceCountsWork` — `TotalRecomputedWork` is the sum of the per-attempt
      work values, asserted against a counting fake predicate.
    - `TestReducePackageNeverTouchesSourceText` — assert by source scan that
      `internal/compiler/reduce` imports no parser/lexer/syntax package and that no
      exported function signature mentions a source string.

    Create `internal/compiler/reduce/predicate.go`.

    Declare `type Signature struct { Axis string; OperationID string; CausalRole string;
    EnginePair string; ForeignCallSequence []string }` and
    `type Predicate func(ctx context.Context, candidate core.Program) (Signature, bool, error)`.

    Declare `func Interesting(seed Signature, candidate Signature) bool` implementing
    D-05-24's conjunction exactly:
    - same `Axis`, AND
    - same `OperationID` — OR, if the operation's position shifted under reduction,
      the same `CausalRole` (the fallback D-05-24 explicitly permits, and the only
      permitted relaxation), AND
    - same `EnginePair`.

    A candidate that still fails, but on a different axis, at a different operation,
    or between a different engine pair, is REJECTED as uninteresting. This is what
    stops the reducer from wandering to a different bug.

    Additionally reject any candidate whose `ForeignCallSequence` differs from the
    seed's on the causal path — a changed call order, a changed symbol, or a
    changed argument shape. This is the local analogue of C-Reduce's UB-drift
    failure: the foreign boundary is the one place in this language where UB
    genuinely lives, so a reduction that perturbs it is producing a different
    program, not a smaller one.

    Declare `func SignatureFromDisagreement(d *session.Phase5EngineDisagreement,
    program core.Program) Signature` — OR, if importing `session` from `reduce`
    would create an import cycle, define the mapping in the opposite direction in
    plan 05-12's wiring file and keep `reduce` dependency-free. Check the import
    graph before choosing; `reduce` staying a leaf package is preferable.
