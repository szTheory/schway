<objective>
Prove the entire agent loop end-to-end on ONE interprocedural defect class before
any other work in this phase is built on the assumption that it works: `check`
attaches a real repair to `check.interprocedural_loan_liveness`, `lang --json check`
publishes it, and the untouched `cmd/lang-repair` driver applies it and the program
re-checks clean.

Purpose: this is the phase's tracer slice. Every remaining plan (blame resolver,
two more repair classes, explain attribution, held-out corpus) assumes this path
is real. If the `Error` -> `ErrorWithRepairs` conversion, the `:stmt` span channel,
or the driver's byte-splice does not compose, it is far cheaper to learn it here
than after ten layers are committed.

Output: one shipped repairable interprocedural class, four re-pinned diagnostic
IDs, the `testdata/phase13/` corpus root, and a written record of what
`antitheater_test.go` demands of any new defect class.

**The objection to answer first (D-13-11):** "rustc refuses to auto-fix borrow
errors." Lang can honestly ship `MachineApplicable` here because `take` is a pure
compile-time ownership transfer with no observable runtime effect — relocating it
past a call cannot change program meaning, whereas reordering in Rust can move a
`Drop`. State this in the code comment at the emission site.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `check` -> `lang --json check` stdout | Repair `Span` and `Replacement` text leave the compiler as untrusted-by-the-driver JSON |
| `lang --json check` stdout -> `cmd/lang-repair` | The driver decodes a byte span and splices replacement text into a source file it then overwrites |
| `cmd/lang-repair` -> the developer's source file | The only write path in the loop; a wrong span or replacement silently corrupts real source |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-13-01 | Tampering | `applyRepair` byte splice | high | mitigate | Repair `Span` comes from the `:stmt` channel only; `cmd/lang-repair`'s existing `CodeSpanOutOfRange` refusal (repair.go:237-242) refuses rather than clamps an out-of-range span, and `TestRepairDriverNeverOpensSourceOutsideSpan` stays green (verified by the full-suite run) |
| T-13-02 | Tampering | `move_after_interprocedural_loan` Replacement text | high | mitigate | Replacement is reconstructed from `core.Place.Name` + `CalleeID` inside `check`, never echoed from the source file; if any name is empty or a `:stmt` span is missing, zero repairs are emitted (fail-closed) rather than a partial edit |
| T-13-03 | Spoofing | A repair that makes the program check clean but mean something else | high | mitigate | D-13-11's argument is load-bearing and stated at the emission site: `take` has no observable runtime effect, so the reorder is semantics-preserving; Task 3's re-check-clean assertion plus the full suite is the gate |
| T-13-04 | Repudiation | Silent diagnostic-ID churn hiding an unintended identity change | medium | mitigate | Exactly four rows re-pinned, asserted by `git diff` scope on `check_ordering_stability_test.go` plus `TestInterproceduralDiagnosticOrderingStability` |
| T-13-05 | Elevation of Privilege | Driver escaping its protocol-only tier | medium | mitigate | `git diff --quiet` on driver source plus `TestRepairDriverImportsStayOutsideInternal` |
| T-13-SC | Tampering | npm/pip/cargo installs | low | accept | This phase adds zero dependencies; Go stdlib only, consistent with the project's zero-external-production-dependency record. No package-legitimacy audit applies because no package manager install task exists in this plan. |
