# Phase 32.1 Plan 04: Abort-like defect parity Summary

The interpreter's fixture and file routes now accept every abort-like defect (byte-index OOB, checked-add overflow, remainder by zero, user `defect`) with a live owner, matching native exit 65 and stderr, while all other live-resource terminals stay refused.

## Accomplishments

- `isByteIndexDefect` became `isAbortLikeDefect`: final `function.defected` event with `:event:defected` suffix attributed to one of four operation kinds; both call sites use it.
- Session subtests for the user defect and overflow flipped from "stays rejected" to acceptance with exact reasons; a remainder-by-zero subtest was added (dated comment 2026-10-12, Phase 32.1, D-09/D-25).
- White-box predicate test covers all four accepted kinds and refused call/output ops, nonlocal, call-depth, unknown op, wrong event kind, returned, typed_failure, empty events.
- Native parity test builds each variant in `t.TempDir()` (no new `.schway` corpus file), at O0 (plus O3-LTO for one variant), asserting exit 65, empty stdout and stderr `schway: <reason>` (`schway app: boom` for the user defect) equal to the interpreter's final event output.
