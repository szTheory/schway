### Pattern 1: typed sentinel mapped at the command wrapper (D-01)
**What:** `var ErrRunInputRequired = errors.New("run input required")` returned from the two `!ok` sites; each `Run*CommandFile` checks `errors.Is` before its generic mapping and returns `protocol.New("run", protocol.StatusUsage)` with `diagnostic.Error("tool.run_input_required", diagnostic.Span{}, <static message>)` and `completeCommand(result, started, 1)`.
**When to use:** both engines, identical constants so JSON is byte-identical (verified: both engines produced the same `result:` and `diagnostic:` IDs and `recomputed_work=1` in the probe).
**Example (verified in the scratch clone):**
```go
// Source: probe patch against internal/compiler/session/session.go (scratch clone)
if errors.Is(err, ErrRunInputRequired) {
    result := protocol.New("run", protocol.StatusUsage)
    result.Diagnostics = []diagnostic.Diagnostic{diagnostic.Error("tool.run_input_required", diagnostic.Span{}, runInputRequiredMessage)}
    return completeCommand(result, started, 1), nil
}
```
In `RunNativeCommandFile` the check must precede the existing `errors.As(err, &mismatch)` / `*native.ToolError` branch (session.go:1618-1633).
**Message:** a single package constant, no `%s`, no path, no parameter name, e.g. "run supplies no input for this entry's parameter; use build, then app run ARTIFACT -- INPUT".

### Pattern 2: allow-list re-pin with dated comment (D-04)

### 2. D-08 (ByteView entry refusal)

- Today `check.unexecutable_shape` / `use_executable_shape` is emitted only by `checkLinear` (`check.go:3924-3943`) and the foreign-call path (`4193-4198`) via `diagnostic.ErrorWithRepairs("check.unexecutable_shape", function.Parameter.Span, msg, causes, diagnostic.Repair{Kind:"use_executable_shape", Detail:"Byte or Buffer"})`. `executableShape` (`check.go:6742`) accepts Byte, Buffer, PathToken, U64. A `ByteView` function with statements never reaches it: `check.go:342` sends it to `checkScalarFunction` (`scalar.go:34`), which admits a ByteView parameter.
- The entry is *not* known inside `check.Program` (it never calls `callgraph.EntryFunction`); `session.resolveEntry` knows it.
- **Conflict found:** `examples/checksum/adler32.schway` (module `adler32`, `export { fn adler32 }`, no `main`) resolves, when checked alone, to `adler32(bytes: ByteView)` (manifest row: `EntryShape single-root`, `Entry adler32`). A rule "refuse ByteView on the resolved entry" refuses it, contradicting D-08's required negative control. It is the only ByteView entry parameter in the whole corpus (scan of 162 `.schway` files).
- **Recommendation (ONE):** in `check.Program`, before the `if function.Body.Linear != nil` fork at `check.go:~340`, refuse when `function.Body.Linear != nil && function.Name == "main" && function.Module == "" && function.Parameter.Type.Constructor == "ByteView" && len(Arguments)==0`; `continue`. This is precedence tier 1 of `callgraph.EntryFunction` (entry-module `main`, `callgraph.go:339-347`), matches 29 WR-02's literal repro (`fn main(b: ByteView)`), keeps every library root (`adler32`) and every non-entry loop function legal, gives a parameter span (`function.Parameter.Span`), and refuses on every route that calls `check` (check, build, both run engines, app verify, explain, query). ## Common Pitfalls

### Pitfall 1: first code commit breaks the living-claims test
**What goes wrong:** `stale_bound_claim` (digest at HEAD no longer equals the bound marker).
**Why:** markers were bound at 079e112f's digest; any digest-path commit moves it.
**How to avoid:** wave-0 reopen plan; verify with the focused run before the first code commit.
**Warning signs:** `receipt problems: [stale_bound_claim]`.

### Pitfall 2: inventory line pin
**What goes wrong:** `TestPhase16PublicEmitterConsumerInventory` red after any `session.go` edit.
**How to avoid:** put new session code in a new file; edit `session.go` in exactly one plan; re-pin `session.go:EmitNative:3098` as that plan's last task and re-run after any later `session.go` touch.

### Pitfall 3: a "refuse before engine" test that is vacuous
`runNativeChecked` already stops before the runner today, so "zero runner calls" passes before and after. The test is a regression guard (ordering), not the distinguishing assertion; the distinguishing assertions are status `usage_error`, exit 64 and the code.

### Pitfall 4: D-08 keyed on the resolved entry
Refuses `adler32.schway`. Key on entry-module `main`.

### Pitfall 5: usage grammar
Inner `" | "` and route-first-word constraints (see Anti-Patterns). Also `phase32UsageProblems` requires each alternative's first word to be a route.

### Pitfall 6: peer tiers without module filter
