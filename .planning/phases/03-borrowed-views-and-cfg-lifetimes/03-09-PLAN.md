<fixture_disposition>
## The `exclusive_borrow_clean` / `relay` hazard — decided, not deferred

03-06 deliberately dropped a `check.go`-side rejection for omitted origins because it broke
the already-shipped `exclusive_borrow_clean` / `relay` fixture (03-06-SUMMARY.md, Deviations
#1). Closing GAP 2 forces an explicit decision. **The decision is: scope the new check to the
publication path only.**

- The omitted-origin gate lives in `originvalidate.ValidatePublished`, whose only caller is
  `session.InterfaceExportCommandFile` (`internal/compiler/session/session.go`, the
  `lang interface export` command). It is NOT restored in `internal/compiler/check/check.go`.
- **`internal/compiler/check/check_exclusive_test.go`** — the inline `exclusive_borrow_clean`
  module source declaring `fn relay(buffer: Buffer) -> Buffer`, inside
  `TestExclusiveBorrowLowersToCore` — is **left byte-unchanged and stays passing**.
  `session.Check` on it must still return zero diagnostics.
- **`testdata/phase3/public_view_omitted.lang`** (new) carries the same borrow-derived,
  unannotated return shape as an export-path control, so the behaviour is pinned by a
  fixture rather than by an inline test string.
- **No spelled opt-out is added.** No new keyword, no new annotation, no new grammar: a
  program that wants to publish a borrow-derived return declares `borrow(path)` /
  `borrow mut(path)`, which the language already spells. Adding an opt-out would create a
  second way to say "this aliases the caller" and is out of scope.
- Consequence, stated plainly: `lang check` and `lang run` keep accepting the `relay` shape
  exactly as today; `lang interface export` on the same source newly refuses to publish it.
  That asymmetry is the fix 03-DEBT.md D-03-02 itself prescribes, and it is the reason the
  03-06 breakage does not recur.
</fixture_disposition>
